> Дата: 2026-10-30. Ветка: stage-3-planetary-physics.

## 1. Замысел

Evolution Wars — симулятор планетарных миров и их эволюции. К стадии 4.0 проект
представляет собой генератор миров (каталоги + PRNG + причинная цепочка) с
начальной физической моделью (этап 3): орбиты, энергетический баланс, фазовый
скрининг, стехиометрическая химия, качественная геология.

Цель Stage 4.0 — спроектировать целевую научную архитектуру, внутри которой
существующие функции станут частными случаями, а не будут выброшены.

**Мы не переписываем движок на этом этапе.** Все документы в `docs/science/`
описывают проект; в них явно разделяется: реализовано / частично / отсутствует /
невозможно без данных.

## 2. Границы научной модели

### 2.1 Что модель обязана делать честно

1. **Законы сохранения.** Масса, элементы, заряд, энергия учитываются явно.
   Атомы не возникают и не исчезают (элементный баланс реакций уже проверяется).
2. **Единицы.** Внутренние расчёты — только SI (кг, м, К, Па, Вт, Дж, моль, с).
   Привычные единицы (а.е., M⊕, atm, бар) — только конвертация на границе UI.
3. **Достоверность каждого значения.** Каждая физическая величина несёт метку
   достоверности, источник, метод, диапазон применимости (см. §4).
4. **Unknown ≠ 0.** Если данных недостаточно — значение `null` c
   `confidence: 'unknown'`. Подмена нулём или «типичной константой» запрещена
   без явной пометки `game_assumption`.
5. **Приближение не выдаётся за точность.** Скрининговые показатели (например,
   S_i = p_i/P_sat) никогда не называются равновесным расчётом.
6. **Разделение температурных величин.** Эффективная температура звезды,
   равновесная температура (T_eq), температура поверхности, профиль
   атмосферы, температура резервуара и локальная температура реакции —
   РАЗНЫЕ физические величины с разными источниками и областями
   применимости; ни одна не подменяет другую (PHYSICS_ARCHITECTURE §5.1).

### 2.2 Что модель НЕ обязана делать (объявленные упрощения)

- Не 3D GCM: климатический контур строится снизу — энергетический баланс →
  одномерная радиационно-конвективная модель → интерфейс для внешних решателей.
- Не спекциальная N-body в первой итерации: аналитическая модель Кеплера +
  явные проверки устойчивости (Хилл, Рош) + интерфейс интегратора.
- Не линейная спектроскопия онлайн: сечения поглощения поставляются
  предрассчитанными таблицами (HITRAN2024/ExoMol → k-коэффициенты; версии фиксировать, базы не смешивать), а не
  считаются в рантайме.
- Не полная геохимия в воде: PHREEQC-уровень — целевой ориентир, первый шаг —
  каркас потоков между резервуарами с законом сохранения элементов.

### 2.3 Категорически вне модели

- Вымышленные «кинетические константы» и «тепловые мощности» без источника.
- Смешивание PRNG (генерация начальных условий) с численным решением ОDE
  физической эволюции.
- Использование результата одной модели за пределами её области применимости
  (например, T_eq как температура поверхности).

## 3. Иерархия модельных объектов (целевая)

```text
Космологический контекст (эпоха, возраст Вселенной)
└── Планетная система (барицентр, система отсчёта)
    ├── Первичный гравитационный объект (звезда / компактный остаток / планета-родитель)
    ├── Источники излучения[] (звезда, аккреция, внутреннее тепло)
    └── Тела[] (планета / карликовая планета / спутник / малое тело / кольцо)
        ├── Орбитальные элементы (относительно родителя)
        ├── Тело: масса, радиус/фигура, вращение, наклон оси, момент инерции
        ├── Внутреннее строение: ядро / мантия / кора (слои, EOS)
        └── Резервуары[]: атмосфера, океан, лёд, кора, мантия, ядро, аэрозоли
            ├── Фазовая система: многокомпонентные равновесия
            ├── Химическая система: инвентарь, реакции, потоки
            └── Тепловой контур: приток/отток, парниковая связь
```

Ключевые разделения (уже частично проведены в этапе 3, расширяются):
- гравитационный первичный объект ≠ источник излучения ≠ родительское тело;
- система отсчёта и барицентр — явные сущности;
- свободно плавающие системы — отдельный класс (без звёздной орбиты);
- звёздная эволюция (светимость во времени) ≠ возраст Вселенной.

## 4. Единая модель достоверности

Уже реализована шкала `ScientificConfidence` (established, derived, estimated,
hypothetical, game_assumption, unknown) и обёртка `PhysValue` (значение, единица,
диапазон, метод, формула, источник, применимость, неопределённость).

Целевые расширения (проект):
1. **Категории происхождения** (дополняют confidence):
   - `observed` — наблюдаемое значение (миссии, эфемериды);
   - `experimental` — экспериментальное (NIST/ATcT/JPL);
   - `reference_range` — справочный диапазон;
   - `derived_computed` — производная расчётная величина;
   - `numerical_approximation` — численное приближение (схема, шаг, оценка ошибки);
   - `theoretical_estimate` — теоретическая оценка;
   - `game_assumption` — игровое допущение (без научного содержания);
   - `unknown` — неизвестно.
2. **Версионирование данных**: `sourceVersion` (например, «ATcT ver. 1.122»,
   «HITRAN2024», «CODATA 2022»), дата проверки, идентификатор записи каталога.
3. **Распространение неопределённости**: правила комбинирования (линейные
   формулы — квадратичное суммирование; нелинейные — интервальный/Монте-Карло
   уровень на этапе 4.10).
4. `unknown` никогда не превращается в число неявно; для этого нужен отдельный
   явный шаг с пометкой.

## 6. Принципы неприкосновенности

1. Лучше явно обозначенная упрощённая модель, чем фиктивная точность.
2. Каждое расширение подсистемы обязано проходить регрессионные тесты остальных.
3. Никакая подсистема не продвигает время самостоятельно — только через
   единое ядро симуляции (проект SIMULATION_ENGINE).
4. Данные отделяются от кода; каталоги версионируются; миграции сохранений —
   обязательная часть любого изменения схемы.
5. UI никогда не вычисляет физику; он только отображает `PhysValue` через
   форматтеры ядра.
