## 1. Scope и не-цели

### 1.1 Scope (что специфицируется)

- Явный ОТДЕЛЬНЫЙ API неидеального газофазного химического равновесия:
  та же постановка задачи, что у `solveEquilibrium` (минимизация полной
  энергии Гиббса при элементных и зарядовых ограничениях), но с
  компонентными коэффициентами фугитивности phi_i из PR EOS
  (`Core/pengRobinsonMixture.ts`) вместо идеальногазового phi_i = 1.
- Только vapor-ветвь PR-кубики смеси; только виды и пары, полностью
  покрытые каталогами 4.4.4.1 (чистые параметры) и 4.4.4.3 (kij).
- Переиспользование существующего внутреннего идеальногазового решателя
  `solveEquilibrium` БЕЗ изменения его кода и контракта.

### 1.2 Не-цели (явно запрещено на этом и до отдельных подэтапов)

- Не менять `solveEquilibrium`, его типы, статусы и поведение: все
  существующие идеальногазовые результаты и тесты остаются побитово
  прежними. `result.model` идеального решателя НЕ меняется.
- Не считать конденсацию, LLE, появление новых фаз, VLE/фазовые
  расщепления внутри реактивной задачи: решение — однофазный vapor
  кандидат; отсутствие конденсированной фазы НЕ маскируется и НЕ
  проверяется (явное предупреждение в результате).
- Не активировать PR автоматически: новый API вызывается только явно;
  идеальногазовый путь не переключается на PR ни при каких условиях.
- Не подставлять kij = 0 молча; не повышать evidence-статусы;
  не расширять диапазоны применимости BIP.
- Не объявлять стационарную точку доказанным глобальным минимумом
  Гиббса и не вводить статусы stable / globally_stable.
- Непрерывный validated TPD error bound остаётся NO-GO
  (TPD_CONTINUOUS_ERROR_BOUND.md); конечный multi-start не является
  доказательством глобальной устойчивости — эти статусы не пересматриваются.
- Не менять golden baseline и схему сохранений.

## 2. Связь химического потенциала с PR fugacity

### 2.1 Химический потенциал в PR-смеси

Для компонента i газовой смеси при (T, P, x):

    mu_i / (R T) = g_i_deg / (R T) + ln(x_i P / p_deg) + ln(phi_i(x, T, P))

где g_i_deg/(RT) — стандартная энергия Гиббса при температуре задачи
(из NASA-7 записей каталога, конвенция p_deg данных), x_i — молярная
доля, p_deg — давление стандартного состояния, phi_i — компонентный
коэффициент фугитивности PR EOS. f_i = x_i phi_i P — фактическая
формула фугитивности, реализованная в `computePengRobinsonMixture`
(поле `fugacityPa`), что подтверждает согласованность знаков.

### 2.2 Условие равновесия и фактическая параметризация solveEquilibrium

Условие стационарности при элементных ограничениях и заряде:

    g_i_deg/(RT) + ln(x_i P / p_deg) + ln(phi_i) = SUM_k lambda_k a_ki + lambda_charge q_i

Сверка с фактическим кодом `Core/equilibrium.ts` (не по формуле из ТЗ
вслепую): в `solveEquilibrium` заряд — ОБЫЧНАЯ строка баланса
(`buildBalanceRows` добавляет строку с именем charge наравне с
элементами), поэтому lambda_charge — просто ещё один элемент вектора
двойственных переменных pi (после редукции строк). Состав
параметризован как

    x_i = exp( - g_i_deg/(RT) + ln(p_deg/P) + SUM_j pi_j c_ji ),

где c_ji — коэффициенты редуцированных строк (элементы + заряд).
Подстановка в условие стационарности даёт точно mu_i/(RT) = SUM_j pi_j c_ji
при phi_i = 1. Следовательно, PR-обобщение сохраняет структуру:

    x_i = exp( - g_i_deg/(RT) + ln(p_deg/P) + SUM_j pi_j c_ji - ln(phi_i(x)) ),
    G/(RT) = n_tot * SUM_i x_i * ( g_i_deg/(RT) + ln x_i + ln(P/p_deg) + ln(phi_i(x)) ).

### 2.3 Почему однократная поправка g_i_deg += ln(phi_i) недостаточна

ln(phi_i) зависит от текущего состава x (через a_mix, b_mix, S_i, Z и
правила смешения с kij). Однократный сдвиг стандартных энергий решает
только задачу с phi, замороженным в одной точке состава; результат не
удовлетворяет условию стационарности с фактическим phi(x). Требуется
согласованное нелинейное решение: ln(phi_i) должен быть вычислен в той
же точке x, в которой выполнена стационарность (неподвижная точка),
либо система должна решаться целиком с производными phi по составу.

### 2.4 Согласование стандартных давлений

Член ln(x_i P / p_deg) и ln(phi_i) обязаны быть отнесены к ОДНОМУ
стандартному состоянию: g_i_deg каталога NASA CEA отнесён к
идеальногазовому p_deg = 1 бар (конвенция набора данных, Stage
4.4.3/C4). PR phi_i — свойство EOS, не зависящее от выбора p_deg,
но комбинация ln(x_i P/p_deg) + ln(phi_i) корректна только при p_deg
задачи, совпадающем с конвенцией данных видов. Несовместимое p_deg —
отказ (invalid_input), как в существующем адаптере каталога; пересчёт
g_deg на другое p_deg не проектируется.

## 3. Интерфейс с текущим solveEquilibrium

### 3.1 Внутренний решатель переиспользуется без изменений

Внутренняя задача на каждой внешней итерации — точно задача
`solveEquilibrium` с заменой g_i_deg/(RT) -> g_i_deg/(RT) + ln(phi_i_used):

- все гарантии внутреннего решателя (редукция строк, C1/C2/C4,
  линейный поиск, честные статусы) сохраняются без изменений;
- сходимость ВНУТРЕННЕЙ задачи означает: балансы элементов/заряда
  выполнены для состава x^(k+1), и стационарность выполнена с phi,
  ЗАМОРОЖЕННЫМ на итерации k. Это НЕ доказывает стационарность полной
  PR-задачи — проверка неподвижной точки по phi обязательна (§7).

### 3.2 Извлечение двойственных переменных (lambda)

`EquilibriumResult` не публикует pi. ВЫБРАННЫЙ ПУТЬ (реализован в
Stage 4.4.4.8-B1): отдельный диагностический API
`solveEquilibriumWithDiagnostics` в `Core/equilibrium.ts` возвращает
`EquilibriumDetailedSolution { result; stationarityDiagnostics | null }`,
где диагностика вычислена на ФАКТИЧЕСКИХ внутренних значениях
сошедшегося решателя: финальный вектор pi, редуцированные строки
после `reduceRows`, активные/исключённые виды и финальные доли —
без повторного решения и без восстановления базиса заново. Для
каждого активного вида i:

    dualProjection_i = SUM_j pi_j · c_ji   (редуцированный базис решателя)
    muIdeal_i/(RT)   = g_i_deg/(RT) + ln(x_i) + ln(P/p_deg)
    stationarityResidual_i = muIdeal_i − dualProjection_i

Никакого восстановления pi через least squares не выполняется:
необходимые pi и reduced уже существуют внутри решателя, а общий
внутренний путь (private helper) исключает дублирование алгоритма.
Рассматривавшиеся ранее пути ОТКЛОНЕНЫ: опциональное поле в
`EquilibriumResult` меняло бы публичный контракт идеального
решателя; восстановление pi взвешенным least-squares
(min_pi SUM_i w_i (SUM_j pi_j c_ji − mu_i/(RT))^2, w_i = n_tot·x_i)
плохо обусловлено при почти линейно зависимых строках балансов и
восстанавливало бы базис, которым решатель не пользовался.

Границы честности диагностики: `dualProjectionOverRT` — правая часть
условия стационарности на фактическом базисе решателя, а НЕ
самостоятельный химический потенциал; диагностика доступна только
при статусе converged и конечных числах (неконечность — null, не
фиктивные значения); для видов, исключённых нулевыми итогами
элементов, ln(0) не вычисляется (только inactiveSpeciesIds).

### 3.3 Частичное покрытие каталога PR

Каталоги на HEAD: чистые EOS-параметры — co2, n2, ch4, h2o, ar (h2
исключён обоснованно); из 10 пар kij доступны 5 (co2|n2, co2|ch4,
co2|ar, n2|ar, n2|h2o); пары ar|ch4, ar|h2o, ch4|h2o, ch4|n2, co2|h2o —
unresolved (fail-closed).

ПОВЕДЕНИЕ ПРИ ЧАСТИЧНОМ ПОКРЫТИИ — только отказ, никакого молчаливого
исключения видов из элементного баланса:

- Если ХОТЯ БЫ ОДИН вид задачи не имеет чистых EOS-параметров или ХОТЯ
  БЫ ОДНА пара видов (из ВСЕХ пар списка видов, а не только пар с
  положительными текущими долями) не имеет kij — результат
  unsupported_eos_data с ПОЛНЫМ списком дефицитных видов/пар.
- Мотивация строгого требования «все пары»: равновесный состав заранее
  неизвестен — вид с нулевым начальным количеством может получить
  положительную долю в ходе итераций. Это СТРОЖЕ контракта
  `computePengRobinsonMixture` (требует kij только для пар с
  положительными долями); реактивный слой обязан гейтить все пары
  списка видов ДО первого внутреннего решения.
- Молчаливое исключение неподдерживаемого вида из элементного баланса
  ЗАПРЕЩЕНО: оно меняет задачу (создаёт/уничтожает элементы) и
  маскирует дефицит данных. Если вызывающая сторона хочет сузить
  список видов, она делает это ЯВНО на своём уровне — тогда элементный
  баланс строится по новому списку, и это решение видно в вызове.
- Примеры на текущем каталоге: {co2, n2, ar} — поддержано (все три
  пары есть); {co2, ch4} — поддержано; {co2, n2, ch4} — отказ
  (ch4|n2 unresolved); любой вид вне пяти каталоговых — отказ.

## 4. Сравнение численных алгоритмов

Обозначения: K — число редуцированных строк балансов, n — число видов,
F(x) = ln(phi(x)) — отображение состава в компонентные ln phi.

### 4.1 Подход A: полностью связанная система Ньютон/KKT

Математическая система: неизвестные (pi_1..pi_K, n_tot); состав
выражается из стационарности неявно, x_i = exp(-g_i_deg + ln(p_deg/P)
+ SUM_j pi_j c_ji - F_i(x)); невязки — балансы n A x = b и нормировка
SUM x_i = 1. Якобиан содержит плотную связь через производные
dF_i/dx_j: d x_i / d pi_j = x_i (c_ji - SUM_k (dF_i/dx_k) (d x_k / d pi_j)).

Необходимые производные: аналитические dF_i/dx_j. Из формулы ln(phi_i)
в `pengRobinsonMixture.ts` они выражаются через dS_i/dx_j (= a_ij),
d a_mix/dx_j (= 2 SUM_i x_i a_ij), d b_mix/dx_j (= b_j) и dZ/dx_j,
получаемое НЕЯВНЫМ дифференцированием кубики смеси
Z^3 - (1-B)Z^2 + (A-3B^2)Z - A B^3 = 0: dZ/dx_j = -(dP/dx_j)/(dP/dZ).

- Поведение около границ симплекса: экспоненциальная параметризация
  сохраняет x_i > 0; сами dF_i/dx_j остаются конечными, но при
  x_i -> 0 члены вида x_i * dF_i/dx_j в балансовых строках
  вырождаются — система становится плохо обусловленной.
- Риски: (1) dZ/dx_j неограничено растёт вблизи поверхностей слияния
  корней (дискриминант -> 0) и при Z -> B_mix; (2) при переходе между
  топологиями корней (3 корня -> 1 корень) выбранная ветвь Z
  переключается СКАЧКОМ — якобиан разрывен, Ньютон через такую
  поверхность ненадёжен; (3) ошибка в аналитических производных
  легко даёт ложную сходимость (нулевая невязка Ньютон-системы при
  неверном якобиане не проверяет стационарность исходной задачи).
- Критерий сходимости: норма невязки KKT-системы; обязателен
  независимый пост-контроль стационарности по ПРЯМОЙ формуле mu_i
  (не по Ньютон-невязке).
- Обнаружение ложной сходимости: пост-контроль §7.4 + сверка
  производных конечными разностями в тестах (не в production).
- Сложность: O(n^2) на вычисление F и производных + O((K+1)^3) на
  Ньютон-шаг; плотная алгебра.
- Детерминизм: достижим (фиксированный порядок сумм, без случайности),
  но разрывность якобиана на поверхностях переключения ветвей делает
  траекторию чувствительной к binary64-деталям.

### 4.2 Подход B: внешние последовательные замены (successive substitution)

Математическая система: неподвижная точка по phi. Итерация k:
(1) вычислить F^(k) = ln(phi(x^(k))) существующим
`computePengRobinsonMixture` (vapor-ветвь, явная evidencePolicy);
(2) решить ВНУТРЕННЮЮ идеальногазовую задачу с g_eff = g_deg +
F_used^(k) (демпфированное значение, §7.2) — существующим
`solveEquilibrium`; (3) получить x^(k+1); (4) критерий остановки —
по изменению F_used (§7.1).

Необходимые производные: НЕТ (производные F не нужны вообще).

- Поведение около границ симплекса: внутренний решатель уже владеет
  экспоненциальной параметризацией, инициализацией с демпфированием
  и честными отказами; внешнему циклу не требуется новых механизмов.
- Риски: сходимость только линейная; вблизи критических/близких к
  фазовому переходу состояний коэффициент сжатия ||dF/dlnx|| -> 1 —
  застой (stagnation); возможны осцилляции состава (классическая
  проблема SS-циклов — тот же класс трудностей, что в flash, где
  она уже решена демпфированием в ln K с восстановлением).
- Критерий сходимости: max_i |F_used^(k+1) - F_used^(k)| < outerTolerance
  ПЛЮС внутренний статус converged ПЛЮС финальные балансы ПЛЮС
  невязка стационарности (§7.4).
- Обнаружение ложной сходимости: см. §7.5 (пост-контроль неподвижной
  точки, повторное вычисление F в финальной точке, детектор
  осцилляций, запрет сходимости при несходящемся внутреннем решателе).
- Сложность: одна оценка F O(n^2) + кубика O(1) + одно внутреннее
  решение на итерацию; итераций обычно 5–50.
- Детерминизм: полный (никакой случайности, фиксированные бюджеты,
  канонический порядок компонентов в смесевом слое).

### 4.3 Подход C: достаточно ли демпфирования (trust-region / line search)

Демпфированное обновление F_used^(k+1) = F_used^(k) + lambda *
(F^(k+1) - F_used^(k)) с lambda из [1/1024, 1] (тот же диапазон, что
в flash) устойчиво для умеренно неидеальных задач. Недостаточно в
двух режимах: (1) коэффициент сжатия ~1 (критическая область) —
любое фиксированное демпфирование даёт застой; (2) осцилляции
периода >= 2, которые глобальное демпфирование не устраняет быстро.
Меры эскалации: адаптивное lambda (уменьшение при росте невязки
неподвижной точки), детектор осцилляций по нормам последовательных
F_used, и — как ОТДЕЛЬНОЕ будущее расширение — line-search по
направлению SS-шага на норме невязки стационарности или trust-region
на модели G. Полный Ньютон (A) рассматривается как ускоритель ПОСЛЕ
сходимости SS, а не как основной метод.

| Ложная сходимость | риск при ошибке в производных | контролируется пост-проверками | то же |
| Сложность итерации | O(n^2 + (K+1)^3) | O(n^2 + внутренний solve) | как B |
| Детерминизм | чувствителен к ветвям Z | полный | полный |
| Прецедент в кодовой базе | нет | ДА (flash 4.4.4.6) | ДА (flash) |

## 5. Выбранная архитектура и обоснование

ВЫБРАНО: подход B (внешние демпфированные последовательные замены по
ln phi) с внутренним решателем `solveEquilibrium` БЕЗ ИЗМЕНЕНИЙ,
обязательным пост-контролем стационарности и честными статусами
несходимости. Меры подхода C (адаптивное демпфирование, детекторы
застоя/осцилляций) входят в базовую архитектуру; связанный Ньютон (A)
— отложенное возможное ускорение отдельным подэтапом.

Обоснование выбора (не по простоте реализации):

1. Единственный источник PR-математики сохраняется: ln phi вычисляет
   только `computePengRobinsonMixture`; новый код не дублирует кубику,
   правила смешения и kij-гейтинг.
2. Все гарантии идеального решателя (редукция строк, C1/C2/C4,
   финальная проверка всех исходных ограничений, честные статусы)
   наследуются каждой внутренней задачей, а не reimplementируются.
3. Прецедент надёжности в самой кодовой базе: flash 4.4.4.6 использует
   тот же класс внешнего цикла (SS с демпфированием в лог-пространстве
   и восстановлением) и сверен с CoolProp; архитектурный риск
   минимальнее, чем у нового плотного Ньютон-решателя с аналитическими
   производными dZ/dx.
4. Отказы локализованы: любой отказ смесевого слоя (кубика, логарифмы,
   kij, evidence) всплывает как структурированный отказ внешней
   итерации без частичных подстановок.

ЯВНО НЕ ДОКАЗАНО выбранным подходом (фиксируется в результате и в
документации):

- глобальная сходимость внешнего цикла (есть только локальный
  аргумент о сжатии вдали от критических областей);
- что найденная стационарная точка — глобальный минимум G (задача
  нелинейная и в общем случае невыпуклая);
- что vapor-решение устойчиво как фаза (конденсация/LLE вне среза;
  TPD-граница NO-GO);
- отсутствие других стационарных точек (multi-start не вводится;
  если введён — он не доказывает глобальность).

### 6.1 Размещение и имена (проект)

- `Core/prReactiveEquilibrium.ts` — чистая математика внешнего цикла
  (зависимости: `Core/equilibrium.ts`, `Core/pengRobinsonMixture.ts`;
  импортов из Data нет).
- `Data/prReactiveEquilibriumFacade.ts` — каталоговый фасад: lookup
  чистых параметров (4.4.4.1) и kij ВСЕХ пар (4.4.4.3), fail-closed,
  прикрепление provenance (паттерн существующих фасадов).
- Публичное имя вычислителя (проект): `solveReactiveGasEquilibriumWithPengRobinson`.

### 6.2 Запрос (проект)

    PrReactiveEquilibriumRequest {
      temperature: PhysicalQuantity;            // K
      pressure: PhysicalQuantity;               // Pa
      standardStatePressure: PhysicalQuantity;  // Pa; обязан совпадать с конвенцией данных (C4)
      species: readonly PrReactiveEquilibriumSpecies[];
        // id, elements, charge, gStandardOverRT + ОБЯЗАТЕЛЬНЫЕ Tc/Pc/omega с per-field evidence
      binaryInteractions: readonly PengRobinsonBinaryInteractionInput[]; // ВСЕ пары списка видов, без самопар
      elementTotals; chargeTotal;
      evidencePolicy: PengRobinsonEvidencePolicy; // ЯВНАЯ и обязательная
      options?: { maxOuterIterations (по умолчанию 100); outerTolerance (по умолчанию 1e-10); inner: EquilibriumOptions }
    }

### 6.3 Статусы результата и их обоснование

Успех:

- `candidate_converged` — внешний цикл достиг критерия неподвижной
  точки, внутренняя задача converged, балансы и невязка стационарности
  в допусках. Имя сознательно НЕ `converged`: решена локальная
  стационарная задача-КАНДИДАТ, глобальный минимум не доказан (§5).

Несходимость (честные статусы результата, не исключения):

- `max_iterations` — исчерпан бюджет внешних итераций (имя совпадает с
  `EquilibriumStatus`/flash для согласованности реестра статусов
  проекта);
- `stagnated` — прогресс внешнего цикла остановился выше допуска
  (демпфирование достигло пола, норма изменения F_used не убывает
  заданное число итераций; имя вместо `line_search_stalled`, потому
  что внешний цикл — демпфированная неподвижная точка, а не линейный
  поиск);
- `numerical_failure` — неконечности, отказ кубики/логарифмов,
  вырождение внутреннего решателя (агрегируется с сохранением
  исходного кода отказа нижнего слоя).

Отказы данных/входа (структурированный отказ/исключение, как в
существующих слоях):

- `unsupported_eos_data` — единый честный код верхнего уровня «PR-данных
  недостаточно для этого набора видов»: отсутствующие чистые параметры,
  отсутствующий/unresolved kij, T вне верифицированного диапазона пары,
  вид вне каталога. detail сохраняет исходные коды нижнего слоя
  (unknown_component / missing_binary_interaction /
  binary_interaction_applicability) и ПОЛНЫЙ список дефицитов;
- `invalid_input` / `infeasible` / `species_data_missing` — как в
  `EquilibriumError` (повреждённый вход, несовместные балансы, виды
  без NASA-7): те же коды, те же семантики.

Обоснование имён: единый реестр статусов проекта (EquilibriumStatus,
PengRobinsonFlashErrorCode) уже использует max_iterations и
numerical_failure; новые имена (candidate_converged, stagnated,
unsupported_eos_data) вводятся только там, где семантика действительно
новая, и не переиспользуют старые коды с другим смыслом.

### 6.4 Поля успеха (проверяемость)

    PrReactiveGasEquilibriumSuccess {
      status: candidate_converged;
      model: peng_robinson_vapor;   // НЕ ideal_gas; отдельный тип, НЕ расширение EquilibriumResult
      root: vapor;                  // ЯВНО зафиксированная ветвь EOS
      evidencePolicy;
      temperatureK; pressurePa; standardStatePressurePa;
      totalMoles; moleFractions; speciesMoles;

      lnPhiUsed: Record<id, number>;      // финальные использованные ln phi_i
      lnPhiFixedPointResidual: number;    // max_i |ln phi_i(x_final) - lnPhiUsed_i|
      outerIterations; innerIterations;   // внешние и последнего внутреннего решения
      convergence: { outerTolerance; achievedLnPhiChange; finalDamping; innerTolerance };
      stationarityDiagnostics: EquilibriumStationarityDiagnostics | null;
        // Stage 4.4.4.8-B1 (§3.2): фактический диагностический API
        // solveEquilibriumWithDiagnostics — dualProjectionOverRT /
        // idealChemicalPotentialOverRT / stationarityResidualOverRT /
        // maxAbsStationarityResidualOverRT / activeSpeciesIds /
        // inactiveSpeciesIds / basisRowNames на ФАКТИЧЕСКОМ
        // редуцированном базисе внутреннего решателя;

Несходимые статусы несут диагностику (lastLnPhiChange, finalDamping,
oscillationDetected, внутренний статус); состав НЕ выдаётся как
равновесный (поля состава — пустые, как в `failedResult` идеального
решателя), балансы — как невязки от нулевого состава.

### 6.5 Запрещённые семантики

- Сходимость внутреннего идеальногазового решателя НЕ выдаётся за
  сходимость PR-задачи (критерий только по внешнему циклу +
  стационарности).
- Статусы stable / globally_stable НЕ существуют в типе результата;
  отсутствие найденной неустойчивости не доказывает устойчивость.
- candidate_converged не формулируется как «глобальный минимум Гиббса».

## 7. Сходимость и численная устойчивость

### 7.1 Критерий внешней сходимости

candidate_converged требует ОДНОВРЕМЕННО:
1. max_i |F_used^(k+1) - F_used^(k)| < outerTolerance (по умолчанию 1e-10);
2. внутреннее решение последней итерации — статус converged;
3. все исходные балансы элементов/заряда: |невязка| <=
   innerTolerance * max(1, |итог|) (наследуется от C2);
4. lnPhiFixedPointResidual < outerTolerance: ln phi, вычисленный в
   ФИНАЛЬНОМ составе, совпадает с использованным — определение
   неподвижной точки выполнено;
5. stationarityResidual.maxAbs < outerTolerance (в единицах mu/(RT)).

### 7.2 Демпфирование

Обновление F_used в лог-пространстве: F_used <- F_used + lambda *
(F(x_new) - F_used), lambda начиная с 1 и уменьшаемое (деление на 2,
пол 1/1024 — диапазон flash 4.4.4.6) при: отказе внутреннего решателя,
росте нормы изменения F_used, потере физического корня кубики,
осцилляциях. Пол демпфирования + исчерпание бюджета = stagnated, а не
бесконечный цикл.

### 7.3 Детекторы

- Застой: ||dF_used|| < stagnationEpsilon (например, 1e-14) в течение
  M итераций (например, 5) при невыполненном критерии — stagnated.
- Осцилляции: сравнение F_used с F_used двух итераций назад
  (||F^(k) - F^(k-2)|| < ||F^(k) - F^(k-1)|| в течение M итераций) —
  диагностика oscillationDetected = true и эскалация демпфирования;
  при неуспехе — stagnated с этой диагностикой.

### 7.4 Невязка стационарности (защита от ложной сходимости)

Независимо от траектории цикла результат обязан пройти прямую проверку
условия mu_i/(RT) = SUM_j lambda_j c_ji (§3.2): и неподвижная точка по
phi, и нулевые балансы, и нулевая Ньютон-невязка внутреннего решателя
по отдельности не доказывают стационарность полной нелинейной задачи.

Реализованный диагностический механизм (Stage 4.4.4.8-B1):
`solveEquilibriumWithDiagnostics` публикует для внутреннего
идеальногазового решения фактическую двойственную проекцию
dualProjection_i = SUM_j pi_j·c_ji на редуцированном базисе решателя
и невязку stationarityResidual_i = muIdeal_i − dualProjection_i.
Будущий PR-решатель сравнивает ФАКТИЧЕСКИЙ PR-химический потенциал
muPR_i/(RT) = g_i_deg/(RT) + ln(x_i·P/p_deg) + ln(phi_i(x_final)) с
этой проекцией: max_i |muPR_i − dualProjection_i| — полная невязка
стационарности PR-задачи; отдельно контролируется fixed-point остаток
по lnPhi (§7.1 п. 4).

ГРАНИЦА ЧЕСТНОСТИ: эта диагностика проверяет стационарность
ВНУТРЕННЕЙ идеальногазовой задачи с заданным effective g
(согласованность состава, потенциалов и базиса), а НЕ стационарность
полной PR-задачи; для полной задачи дополнительно требуются
fixed-point остаток по lnPhi и приведённое выше сравнение muPR с
проекцией. Допуск невязки стационарности — outerTolerance; её
превышение при выполненных пп. 1–4 §7.1 — numerical_failure
(несогласованность путей).

### 7.5 Дополнительные меры обнаружения ложной сходимости

- повторное вычисление F в финальной точке ВСЕГДА (п. 4 §7.1) —
  защита от использования устаревшего F;
- запрет candidate_converged при любых неснятых предупреждениях
  смесевого слоя об отказах вычисления;
- тест-стратегия: возмущённый старт (§9) — диагностическая, не
  доказательная проверка единственности;
- G-монотонность НЕ требуется и НЕ заявляется: SS по phi не является
  методом спуска по G.

### 7.6 Границы симплекса и вырождения

- Виды с нулевым ИТОГОМ элемента исключаются внутренним решателем с
  ровно нулём — наследуется без изменений; их ln phi в финальной
  точке не вычисляется (нулевая доля не входит в суммы), но
  EOS-параметры такого вида всё равно обязаны присутствовать (§3.3):
  равновесный состав заранее неизвестен.
- Во внешнем цикле составы x^(k) всегда строго положительны
  (экспоненциальная параметризация) — кубика смеси и ln phi получают
  корректный вход; вырожденные состояния кубики (нет физического
  корня, логарифм вне области, degenerate_attraction_limit) —
  структурированный отказ итерации, эскалация демпфирования, затем
  numerical_failure.

### 7.7 Сложность и детерминизм

Итерация: O(n^2) правила смешения + O(1) кубика + O(n) ln phi +
внутреннее решение O(iter_inner * (K^2 n + K^3)). Память O(n^2).
Детерминизм: никаких случайных чисел, времени, порядков по множествам
(только канонические порядки: лексикографический в смесевом слое,
порядок входа во внутреннем); фиксированные бюджеты; binary64 +
сертифицированные логарифмы (certifiedLogarithm) в ln phi. Повторный
вызов с идентичным входом обязан дать побитово идентичный результат
(тест §9).

## 8. Fail-closed правила и provenance

1. Только явный вызов нового API; идеальногазовый путь не затрагивается.
2. Только vapor-ветвь: запрос фиксирован root = vapor; выбранная ветвь
   явно публикуется в результате (root: vapor) с примечанием, что выбор
   ветви — математический выбор кубики, НЕ доказательство устойчивости
   фазы (наследует PENG_ROBINSON_MIXTURE_BRANCH_NOTE).
3. Все виды — с каталоговыми чистыми параметрами; все пары — с
   каталоговыми kij; иначе unsupported_eos_data (§3.3, §6.3).
4. kij = 0 молча не подставляется; асимметричный kij — отказ;
   диапазоны применимости kij проверяются по T (отказ
   binary_interaction_applicability из нижнего слоя сохраняется).
5. evidencePolicy ЯВНА и обязательна; статусы не повышаются;
   предупреждения partially_verified_* проходят насквозь.
6. Provenance EOS и BIP (замороженные структуры каталогов 4.4.4.1 и
   4.4.4.3) прикрепляется к успеху без копирования и без расширения
   системы provenance (фасад не создаёт новых provenance-объектов).
7. p_deg задачи обязан совпадать с конвенцией данных (C4);
   несовместимое p_deg — invalid_input.
8. Конденсация/LLE/новые фазы не рассчитываются; в результате —
   постоянное предупреждение, что однофазный vapor кандидат получен
   БЕЗ проверки фазовой устойчивости и без учёта возможных
   конденсированных фаз; отсутствие конденсированной фазы не
   маскируется идеальным приближением и не утверждается.
9. Повреждённые входы (NaN/Infinity, размерности, пустые списки,
   несовместные балансы) — те же коды, что у идеального решателя,
   без подстановок.

### 9.1 Независимые эталонные расчёты

- `solveEquilibrium` на тех же данных с phi = 1 — эталон предела 1
  (проверяет согласование параметризации и знаков, не физику PR).
- Аналитический 1-D оракул: бинарная изомеризация A <-> B с заданными
  phi_A(x), phi_B(x) — условие x_B phi_B / (x_A phi_A) =
  exp(-Delta g_deg) решается независимой бисекцией; проверяет ВЕСЬ
  внешний цикл (демпфирование, критерии, статусы) на задаче с
  известным ответом.
- mpmath-оракул в benchmark workflow (паттерн 4.4.4.6):
  высокоточная перепроверка стационарных условий mu_i и балансов в
  финальной точке малых задач — валидирует реализацию, не данные.
- CoolProp PQ — только для компонентных/фазовых величин PR (ln phi в
  заданной точке), НЕ для реактивного равновесия как такового;
  сверка валидирует реализацию при каталожных kij, не значения kij.
- Публикуемые примеры CEA (Gordon & McBride) — только качественная
  сверка (другие данные/модели); численное совпадение не заявляется.

## 10. Ограничения и незакрытые научные вопросы

1. Глобальная сходимость внешнего цикла не доказана; коэффициент
   сжатия вблизи критических областей -> 1 (застой возможен by design
   и честно репортится).
2. Стационарная точка не доказана как глобальный минимум G; невыпуклость
   не исследована; multi-start не вводится (а если будет введён — не
   доказывает глобальность).
3. Фазовая устойчивость vapor-решения не проверяется: конденсация,
   LLE, появление новых фаз — вне среза; validated TPD error bound —
   NO-GO (TPD_CONTINUOUS_ERROR_BOUND.md).
4. Точность модели ограничена классическим PR: полярные/ассоциирующие
   виды (h2o) — известные ограничения (предупреждение
   h2o_classical_pr_limitations проходит насквозь); PPR78 не реализован;
   постоянные kij не воспроизводят температурную зависимость.
5. Независимая экспериментальная проверка kij отсутствует: численные
   сверки валидируют реализацию при каталожных kij, а не сами kij
   (наследуется от 4.4.4.6).
6. Диагностика стационарности (Stage 4.4.4.8-B1) экспонирует
   двойственную проекцию ФАКТИЧЕСКИХ потенциалов решателя
   (`solveEquilibriumWithDiagnostics`, §3.2); восстановление lambda
   через least squares НЕ используется (плохо обусловлено при почти
   линейно зависимых строках балансов). Диагностика проверяет
   внутреннюю идеальногазовую задачу с заданным effective g и сама
   по себе не доказывает стационарность полной PR-задачи.
7. Смеси, где PR-каталог покрывает лишь часть химически значимых видов
   (сернистые соединения, ионы и т.п.), неполны: реактивная задача на
   таких наборах честно отказывает, а не деградирует к идеальному газу
   для непокрытых видов (смешанная модель «идеальный газ + PR для
   подмножества видов» — отдельный научный вопрос, здесь НЕ
   проектируется).
8. Энергетика: изотермическая задача; энтальпийный баланс неидеальной
   смеси (residual enthalpy PR) не входит в срез.

## 11. Фактическая реализация Stage 4.4.4.8-B2 (сверка с кодом)

Модуль `Core/prReactiveEquilibrium.ts`; экспорт через `Core/index.ts`.
Зависимости только внутри Core: `equilibrium.ts`
(`solveEquilibriumWithDiagnostics` + типы), `pengRobinsonMixture.ts`
(`computePengRobinsonMixture`, `validatePengRobinsonMixtureInputsStrict` + типы),
`pengRobinson.ts` (типы evidence/политики), `physicalQuantity.ts`,
`thermoFunctions.ts` (универсальная газовая постоянная). Импортов из Data,
PhaseEquilibrium, Atmosphere и UI нет; каталогового lookup нет — все
EOS/BIP-параметры, evidence и ограничения применимости передаются вызывающим
слоем ЯВНО (замороженные provenance-объекты каталогов добавит Data-фасад
следующего подэтапа; возвращаемые `eosInputsUsed`/`binaryInteractionsUsed` —
использованные значения и их evidence/limitations, НЕ каталоговый provenance).

### 11.1 Фактический API

    solveReactiveGasEquilibriumWithPengRobinson(
      request: PrReactiveGasEquilibriumRequest
    ): PrReactiveGasEquilibriumResult

Вход (`PrReactiveGasEquilibriumRequest`): `temperature`, `pressure`,
`standardStatePressure` — `PhysicalQuantity` (размерности проверяются явно;
неверная размерность — `EquilibriumError invalid_input`, без предположений);
`species: PrReactiveEquilibriumSpecies[]` — `EquilibriumSpecies` + ЯВНОЕ
`eos` (Tc, Pc, acentric factor, evidence, crossChecks, limitations; идентификатор
PR-компонента совпадает с `id` вида); `elementTotals`, `chargeTotal`;
`binaryInteractions` — явные kij с evidence и `applicabilityRangeK`;
обязательная `evidencePolicy`; `options` (дефолты по §6:
maxOuterIterations=100, outerTolerance=1e-10, minDamping=1/1024,
stagnationWindow=5, stagnationEpsilon=1e-14, innerOptions для внутреннего
решателя). Все опции валидируются; невалидные значения отклоняются
(`invalid_input`).

Результат — discriminated union:

- `PrReactiveGasEquilibriumSuccess` (только `status: 'candidate_converged'`,
  `model: 'peng_robinson_vapor'`, `root: 'vapor'`): temperatureK/pressurePa/
  standardStatePressurePa, totalMoles, moleFractions, speciesMoles,
  elementResiduals, chargeResidual, lnPhiUsed, lnPhiFixedPointResidual,
  stationarityResidual (по активным видам), maxAbsStationarityResidual,
  stationarityDiagnostics (диагностика B1 финальной итерации), outerIterations,
  innerIterations, finalDamping, dampingEscalations, oscillationDetected,
  gibbsEnergy (Дж, полная энергия PR-задачи, НЕ значение идеальногазового
  результата), eosInputsUsed, binaryInteractionsUsed, warnings, notes,
  interpretationLimitation.
- `PrReactiveGasEquilibriumFailure` (`max_iterations` | `stagnated` |
  `numerical_failure` | `unsupported_eos_data`): код причины (собственный или
  нижнего слоя с префиксами `inner:`/`pr:`), последний fixed-point остаток,
  последний вектор lnPhiUsed и состав внутреннего решения, внутренний статус и
  сообщение, полный список дефицитов EOS/BIP-данных (`deficiencies`), warnings,
  notes. Состав НЕ выдаётся за равновесный.

Статусы `stable` / `globally_stable` / `phase_stable` / `global_minimum` в типы
НЕ введены. Каждый результат несёт постоянное предупреждение
`single_phase_vapor_candidate_without_phase_stability` и
`interpretationLimitation` (однофазный vapor-кандидат без проверки глобальной
фазовой устойчивости и без расчёта конденсированных фаз).

### 11.2 Фактический алгоритм

1. Строгая предитерационная проверка PR-входов ДО первой итерации (§8):
   `validatePengRobinsonMixtureInputsStrict` (validation-only helper в
   `pengRobinsonMixture.ts`, Stage 4.4.4.8-B2) проверяет ВСЕ компоненты и ВСЕ
   пары различных видов — включая виды, которые внутренний решатель исключит
   из-за нулевых итогов элементов: чистокомпонентные параметры (конечность,
   наличие всех полей, без подмен приближениями), evidence по переданной
   политике, каноническая единственность пар (самопары, дубликаты даже при
   согласованном kij, противоречивые kij, неизвестные ID — отказ), конечность
   kij, температура внутри `applicabilityRangeK` каждой пары (если задан).
   Отсутствующий kij — отказ; молчаливый `kij = 0` запрещён. Дефициты
   возвращаются ПОЛНЫМ списком (`unsupported_eos_data`), виды не удаляются,
   element balance не меняется. Production-поведение `computePengRobinsonMixture`
   для прежних потребителей не менялось.
2. Инициализация `lnPhiUsed_i(0) = 0` — только стартовая точка итерации, а не
   утверждение, что смесь идеальна (заметка включается в каждый успех).
3. Итерация k: `gEffective_i/(RT) = g°_i/(RT) + lnPhiUsed_i(k)` → внутренний
   `solveEquilibriumWithDiagnostics` (идеальногазовый решатель БЕЗ изменений;
   §11 ТЗ B2: internals-снапшот собирается только по запросу — обычный
   `solveEquilibrium` не аллоцирует диагностические массивы) → молярные доли
   решения БЕЗ нормализации → `computePengRobinsonMixture` (фактические T, P,
   состав, все явные PR-параметры, строго `root: 'vapor'`, переданная
   evidencePolicy) → целевой вектор `lnPhiTarget`.
4. Fixed-point остаток `r_i = lnPhiTarget_i − lnPhiUsed_i`,
   `fixedPointResidual = max_i |r_i|` по ВСЕМ видам (виды с нулевой долей имеют
   собственный lnPhi — фиктивных ln(0)-невязок нет).
5. Демпфированное обновление в пространстве ln(phi) (не phi):
   `lnPhiUsed_i(next) = lnPhiUsed_i(current) + lambda·r_i`.

### 11.3 Фактическое демпфирование и детекторы

Детерминированное адаптивное правило вынесено в экспортируемый для тестов
helper `prReactiveDampingUpdate(lambda, residual, previousResidual,
residualTwoStepsAgo, minDamping)` (без случайности, времени и
недетерминированного выбора; без callback в публичном API):

- рост нормы fixed-point остатка относительно предыдущей итерации → lambda
  делится пополам (эскалация, счётчик dampingEscalations);
- осцилляция «вниз-вверх» (невязка выросла после локального минимума два шага
  назад) → ещё одно деление пополам и флаг `oscillationDetected`;
- lambda не опускается ниже `minDamping` (1/1024 по умолчанию);
- старт lambda = 1.

Застой: если изменение демпфированного вектора `lambda·residual <
stagnationEpsilon` при fixed-point остатке ≥ outerTolerance в течение
`stagnationWindow` последовательных итераций — честный отказ `stagnated`.
Застой НЕ выдаётся за сходимость: независимый fixed-point остаток всё равно
обязан быть меньше допуска. Исчерпание бюджета — `max_iterations`. Отказ
PR-вычислителя на промежуточном составе (данные уже проверены строго) —
демпфированный откат к предыдущему вектору с уменьшением lambda вдвое; при
lambda = minDamping — `numerical_failure` с кодом `pr:<code>`.

### 11.4 Фактические критерии кандидата равновесия

`candidate_converged` только при ОДНОВРЕМЕННОМ выполнении: внутренний статус
`converged`; диагностика B1 существует и конечна; `max |lnPhiTarget −
lnPhiUsed| < outerTolerance`; изменение демпфированного вектора <
outerTolerance; прямая PR-невязка стационарности каждого АКТИВНОГО вида в
допуске; C2-критерий всех element/charge residuals перепроверен независимо
(допуск внутреннего решателя); все PR-вычисления успешны (предупреждения и
evidence-ограничения сохранены в результате); финальный состав передан в
PR-вычислитель на той же итерации — lnPhiTarget свежие, не устаревшие.

Прямая PR-невязка стационарности (использует диагностику B1):

    muPR_i/(RT) = muIdealEffective_i/(RT) + lnPhiTarget_i − lnPhiUsed_i
    PRStationarityResidual_i = internalStationarityResidual_i
                               + lnPhiTarget_i − lnPhiUsed_i

(внутренняя невязка относится к задаче с `gEffective = g° + lnPhiUsed`, поэтому
полная PR-невязка получается добавлением разности целей и использованных
lnPhi). Сравнивать с допуском только внутреннюю невязку запрещено — это
проверка другой задачи.

### 11.5 Энергия Гиббса

    G/(RT) = nTotal · SUM_i x_i · ( g°_i/(RT) + ln(x_i) + ln(P/p°) + lnPhiFinal_i )

по активным видам (сумма только по x_i > 0 — без ln(0)); умножение на R·T даёт
Дж. Неконечный результат — `numerical_failure`, кандидат не выдаётся.

### 11.6 Фактическая тестовая матрица

`Tests/prReactiveEquilibrium.test.ts`, 25 групп: алгоритм и физические пределы
(идеальногазовый предел vs `solveEquilibrium`; точный нулевой предел
притяжения a_i = 0 при T = Tc·(1+1/kappa)² с предельной формой lnPhi =
(b_i/b)(Z−1) − ln(Z−B); однокомпонентный предел; бинарная реакция с
синтетическими PR-параметрами; НЕЗАВИСИМЫЙ 1-D оракул — бисекция
стационарного уравнения h(xB) = ln(xB/xA) + dg + lnPhiB − lnPhiA; знак и
согласованность lnPhiUsed; перестановочная инвариантность; детерминизм),
сходимость (запрет candidate_converged при внутренней несходимости и при
fixed-point остатке выше допуска; формула PR-невязки при ненулевых lnPhi;
детерминированное демпфирование напрямую — эскалация, осцилляция через две
итерации, пол minDamping; stagnated; max_iterations; границы [minDamping, 1] и
отклонение невалидных опций), fail-closed (отсутствующие параметры и kij, в
том числе у пар с нулевой текущей долей; непринятый evidence, в том числе у
неактивного вида; температура вне применимости BIP; неверные размерности;
NaN/Infinity/повреждённые записи; дубликаты ID и пар, самопары, неизвестные
ID, противоречивые kij; element/charge ограничения; нулевые итоги без ln(0);
отсутствующие поля каталога не заменяются приближениями). Все PR-параметры в
тестах — синтетические тестовые данные с явной пометкой в limitations.
