## 0. Первичные ориентиры и принцип заимствования

Первичные ориентиры литературы:

1. **Michelsen (1982)**, *The Isothermal Flash Problem. Part I.
   Stability*, Fluid Phase Equilibria, DOI
   `10.1016/0378-3812(82)85001-2` — исходная формулировка TPD,
   стационарное условие в приведённых переменных, successive
   substitution, инициализация по Wilson K-values.
2. **Baker, Luks, Michelsen (1982)** — критерий касательной плоскости
   (tangent-plane criterion), на который опирается TPD-анализ
   (Baker–Michelsen-критерий).
3. **GEOS documentation**, раздел Stability analysis (Compositional
   Multiphase Fluid Model) — пример промышленной реализации:
   инициализация лёгкой и тяжёлой пробной фазы по Wilson K-values,
   решение стационарного условия successive substitution, переход к
   negative two-phase flash при обнаруженной неустойчивости. GEOS
   решает ПОЛНЫЙ flash; наш этап 4.4.4.4.2 этого НЕ делает.
4. **Three-Phase Equilibrium Calculations of Water/Hydrocarbon/
   Nonhydrocarbon Systems Based on the EOS in Thermal Processes**
   (PMC8696998) — свидетельство чувствительности stability analysis к
   выбору начальных K-values в трёхфазных водо-углеводородных
   системах: выбор начальных приближений влияет на результат анализа
   устойчивости и должен быть обоснован отдельно.
5. Расширения инициализации в литературе (например, улучшенная
   двусторонняя tangent-plane инициализация Ivanov & Stateva,
   Ind. Eng. Chem. Res., DOI `10.1021/ie061361b`) — ориентир для
   СТРУКТУРЫ набора стартовых точек, НЕ источник числовых порогов.

**Принцип заимствования**: алгоритмические ИДЕИ (Wilson starts,
successive substitution, двухсторонняя инициализация) применимы к
любому EOS-моделированию пробной фазы и переносятся на наш PR-код
(4.4.4.3) с адаптацией к его контрактам. Числовые ПОРОГИ из внешних
реализаций НЕ копируются автоматически: каждый порог ниже выведен из
точности НАШЕГО TPD-evaluator (4.4.4.4.1) и масштаба суммируемых
вкладов. Распространённый в литературе порог −1e−8 НЕ принимается
по умолчанию (см. §6.5).

## 1. Математический контракт

### 1.1. Минимизируемая функция

Та же функция, что в Stage 4.4.4.4.1:

```
TPD(w; z) = SUM_{i: w_i > 0} w_i [ ln(w_i/z_i) + lnPhi_i(w) − lnPhi_i(z) ]
```

— безразмерная dG/RT: расстояние от касательной плоскости к
поверхности энергии Гиббса смеси в точке feed z. Значение и вклады
вычисляет существующий evaluator 4.4.4.4.1 (контракт НЕ меняется:
скаляр + вклады, компенсированная сумма Neumaier, устойчивый
ln(w/z), fail-closed коды). Поиск 4.4.4.4.2 — ОРКЕСТРАЦИЯ вокруг
этого evaluator: генерация пробных точек, пересчёт PR-состояний
пробной фазы, итерации к стационарным точкам, классификация.

### 1.2. Допустимое пространство составов

- носитель feed: supp(z) = { i : z_i > 0 };
- допустимый пробный состав: w_i >= 0, SUM w_i = 1 (в существующем
  допуске суммы состава, БЕЗ нормализации), и
  **supp(w) ⊆ supp(z)**: положительная trial-доля при z_i = 0
  запрещена — это уже структурный отказ `support_violation`
  контракта 4.4.4.4.1 (0·ln 0 не вычисляется, ln(w_i/z_i) при z_i = 0
  не определён);
- никакой epsilon-подмены нулевых долей и никакой молчаливой
  нормализации состава: нарушенная сумма — отказ, а не исправление.

### 1.3. Стационарное условие

В приведённых (ненормированных) переменных Michelsen W_i >= 0
(нормировка w_i = W_i / SUM_j W_j) целевая функция линейна по W:

```
TPD(W; z) = SUM_i W_i [ ln W_i + lnPhi_i(w) − ln z_i − lnPhi_i(z) ]
```

Внутренняя стационарная точка (все W_i > 0 на supp(z)) удовлетворяет
условию, эквивалентному равенству химических потенциалов компонента
в пробной и feed-фазе:

```
ln W_i = ln z_i + lnPhi_i(z) − lnPhi_i(w)   (для всех i из supp(z))
```

Граничные стационарные точки лежат на гранях носителя: подмножество
компонентов с W_i = 0, условие выполняется на оставшемся подмножестве
(поиск на грани — §5). TPD-минимум по допустимому пространству есть
минимум по всем стационарным точкам (внутренним и граничным) и
границам домена; тривиальная точка W = z всегда стационарна
(TPD(z; z) = ровно +0).

### 1.4. Роль ветви корня PR

lnPhi_i(w) берётся из PR-состояния пробной фазы с выбранной ветвью
корня: `vapor` — наибольший физический корень, `liquid` — наименьший
(контракт 4.4.4.3; при единственном физическом корне метки ссылаются
на ОДИН корень — §4). Ветвь — часть моделирования ПРОБНОЙ фазы
(«какой фазе мы приписываем пробный состав»); выбор ветви сам по
себе НЕ является ни доказательством существования такой фазы, ни
доказательством устойчивости/неустойчивости. TPD-поиск обязан
фиксировать ветвь для каждой попытки и НЕ интерпретировать
расхождение ветвей как термодинамический факт.

### 1.5. Стационарная точка ≠ доказанный глобальный минимум

Локальные методы (successive substitution, safeguarded Newton)
сходятся к ОДНОЙ стационарной точке на начальное приближение;
TPD-функция может иметь несколько стационарных точек, а локальный
минимум может не быть глобальным. Поэтому:

- отрицательное TPD в любой ДОПУСТИМОЙ корректно вычисленной точке —
  ДОСТАТОЧНОЕ свидетельство неустойчивости feed-фазы в рамках
  PR-модели (глобальный минимум искать не требуется: он не выше
  найденного значения);
- неотрицательное TPD во всех НАЙДЕННЫХ точках НЕ доказывает
  глобальной устойчивости: конечный набор стартов и итераций не
  гарантирует полноты (см. §6.6, семантика
  `no_instability_found_within_search`).

## 2. Начальные приближения

### 2.1. Обязательный набор стартовых точек

Поиск выполняется из НЕСКОЛЬКИХ детерминированных стартовых точек;
один старт (в том числе один Wilson start) НЕ считается достаточным
обоснованием полноты поиска. Предлагаемый минимальный набор для
носителя supp(z) из s компонентов:

1. **feed** — w = z. Тривиальная стационарная точка с TPD = 0;
   включается как базовая попытка (smoke-проверка сходимости
   итераций), но тривиальный результат не считается «найденным
   минимумом» и не может дать `unstable_detected`.
2. **wilson_light** — лёгкий пробный состав: w_i ∝ z_i · K_i.
3. **wilson_heavy** — тяжёлый пробный состав: w_i ∝ z_i / K_i.
4. **uniform** — равномерный состав по носителю: w_i = 1/s для
   i из supp(z).
5. **pair_{i,j}** — парные составы w_i = w_j = 0.5 для каждой
   упорядоченной пары i < j из supp(z) (O(s^2) точек,
   детерминированный порядок).

Парные и uniform-старты дополняют Wilson-старты: Wilson-корреляция
настроена на паровое равновесие и может промахиваться мимо
LLE-подобных минимумов; независимая литература прямо отмечает
зависимость результата stability analysis от начальных K-values
(§0, пункт 4). Тривиальный feed-старт не является независимой
проверкой и в подтверждениях не учитывается.

### 2.2. Wilson K-values: доступность данных (проверено)

Корреляция Wilson (1969):

```
K_i = (Pc_i / P) · exp( 5.373 · (1 + omega_i) · (1 − Tc_i / T) )
```

Требуемые Tc_i, Pc_i, omega_i УЖЕ доступны в контракте
4.4.4.3: `PengRobinsonMixtureComponentInput` содержит
`criticalTemperatureK`, `criticalPressurePa`, `acentricFactor` —
это те же валидированные каталогом (4.4.4.1) параметры, которые
evidencePolicy уже приняла при расчёте feed-состояния. Wilson
starts НЕ требуют нового provenance и НЕ вводят новых чисел: они
переиспользуют принятые параметры. Если политика отклонила
параметры какого-то компонента, PR-расчёт feed невозможен и поиск
не начинается вовсе (отказ раньше). Никакие параметры не
восстанавливаются и не выдумываются. Случай «параметр есть, но его
статус неприемлем для политики» невозможен без неприемлемости
всего расчёта.

### 2.3. Численно устойчивая нормализация стартов

Старты нормируются ТОЛЬКО по положительным членам и в log-space:
для членов c_i = z_i·K_i (или z_i/K_i) вычисляется
ln c_i = ln z_i + ln K_i, затем
`ln w_i = ln c_i − logsumexp(ln c)`. Это исключает и
переполнение/исчезновение при экстремальных K, и epsilon-подмену:
члены с z_i = 0 в носитель не входят (структурно, см. §1.2),
z_i > 0 гарантирует конечный ln z_i. Компоненты с выродившимся
(ноль после нормировки в double) w_i просто не входят в пробный
носитель — support-контракт evaluator обрабатывает это штатно.

### 2.4. Итерационный метод: successive substitution

Из стационарного условия §1.3 стандартное обновление Michelsen
(successive substitution):

```
ln W_i^{(k+1)} = ln z_i + lnPhi_i(z) − lnPhi_i(w^{(k)})
```

на каждом шаге требуется пересчёт PR-состояния пробной фазы для
нового состава (та же ветвь корня, те же T/P/kij, §3.2) и один
вызов TPD-evaluator для текущей точки. SS глобально сходится в
большинстве практических случаев и прост; его слабость — линейная
сходимость вблизи критической точки и возможность схождения к
не-минимальной стационарной точке, что компенсируется набором
стартов (§2.1) и честной классификацией (§6.6).

### 2.5. Safeguarded fallback (требование, не реализация)

При плохой сходимости SS (истощение бюджета итераций без выполнения
критериев §6.1–6.4) допускается ЛОКАЛЬНЫЙ safeguarded fallback в
переменных ln W (позитивность гарантирована параметризацией):
quasi-Newton (BFGS) или safeguarded Newton с численным якобианом
конечными разностями по ln W. Ограничения дизайна:

- аналитические производные lnPhi по составу в проекте НЕ
  реализованы (интерфейс якобиана — предмет отдельного будущего
  этапа), поэтому якобиан только численный, с явной ценой в
  вычислительном бюджете (s дополнительных PR-пересчётов на шаг);
- fallback НЕ освобождает от лимитов итераций и НЕ меняет семантику
  результатов; неудавшийся fallback — та же классификация
  (§6.6), что и неудавшийся SS;
- глобальные методы (туннелирование, интервальный анализ,
  стохастика) в 4.4.4.4.2 НЕ предлагаются — вне бюджета этапа;
  невозможность гарантировать глобальный минимум закрыта семантикой
  `no_instability_found_within_search`, а не алгоритмом.

## 3. Root branches

1. Для каждого стартового состава поиск выполняется по ОБЕИМ
   физическим ветвям PR-корня пробной фазы: `vapor` (наибольший
   физический корень) и `liquid` (наименьший), если
   `distinctPhysicalRootCount >= 2` (контракт 4.4.4.3:
   `physicalRoots`, `hasDistinctBranches`).
2. Если физический корень ОДИН, метки vapor/liquid ссылаются на
   один корень (предупреждение `single_physical_root` в 4.4.4.3):
   поиск НЕ выдаёт две «независимые» ветви. Попытки с обеими метками
   обязаны быть помечены `singleRootDeduplicated: true`, и в
   подтверждениях поиска они считаются ОДНОЙ попыткой.
3. Ветвь feed-фазы фиксирована входом вызывающего кода и не
   перебирается.
4. Каждая попытка сохраняет ветвь в результате (§7). Выбор ветви —
   моделирование пробной фазы, НЕ доказательство её физического
   существования и НЕ доказательство устойчивости.

## 5. Границы симплекса

1. **Внутренний поиск**: старты §2.1 на полном носителе supp(z);
   SS-итерации §2.4 сохраняют носитель (ln W_i конечен при z_i > 0).
2. **Грани носителя**: минимум TPD может лежать на грани (часть
   W_i = 0). Стратегия: тот же поиск (старты + SS) выполняется на
   каждом собственном непустом подмножестве носителя — гранях
   supp(z). Число граней 2^s − 2 (s = |supp(z)|); для текущего
   каталога (до 5 компонентов) полное перечисление стоит <= 30
   поисков — дёшево; дизайн фиксирует лимит полного перечисления
   `s <= 5` (каталог потолок). При s > 5 — детерминированная выборка
   граней (например, все грани размера s−1 и s−2) и ЧЕСТНАЯ
   маркировка `faceEnumeration: 'partial'` с перечнем обследованных
   подмножеств.
3. **Вырождение на границе итераций**: если SS-итерация загоняет
   компонент к нулю (w_i → 0 в double), попытка завершается на
   достигнутой точке, и старт повторяется на соответствующей грани —
   граничный минимум ищется штатным поиском грани, а не «дотяжкой»
   нуля.
4. **Честная маркировка**: результат всегда содержит
   `faceEnumeration` ('complete' | 'partial') и список обследованных
   подмножеств. Поиск только по внутренним точкам НЕ выдаёт
   формулировку, эквивалентную доказательству глобальной
   устойчивости: `no_instability_found_within_search` описывает
   РЕАЛЬНО выполненный поиск и только его.

## 6. Сходимость и численная классификация

### 6.1. Stationarity tolerance

Невязка стационарности активного носителя попытки:

```
r_stat = max_{i in supp(W)} | ln W_i − ln z_i − lnPhi_i(z) + lnPhi_i(w) |
```

Предложение: **sigma_stat = 1e−10**. Обоснование: точность
TPD-evaluator (4.4.4.4.1) — регрессии воспроизводят значения до
~1e-24 (устойчивый ln(w/z), Neumaier), а ulp-масштаб самих lnPhi
~1e-16·|lnPhi|; невязка 1e−10 на 4–6 порядков выше машинного шума
итераций и на несколько порядков ниже любого физически осмысленного
масштаба lnPhi (O(0.1–10)).

### 6.2. Лимит итераций

Предложение: **N_max = 300** successive-substitution обновлений на
попытку (грань × ветвь × старт). Обоснование: SS сходится линейно;
300 итераций покрывают и медленные случаи при типичных темпах
сходимости, и остаются дешёвыми в детерминированном бюджете
(<= 300 × PR-пересчётов на попытку). Литературные лимиты (сотни
итераций у Michelsen) подтверждают порядок величины; точное
значение — наше, по бюджету.

### 6.3. Критерий изменения состава

Предложение: **sigma_w = 1e−12** в log-space:
`max_i |ln W_i^{(k+1)} − ln W_i^{(k)}| <= 1e−12`. Состав
отслеживается в логарифмах (§2.3), поэтому критерий бережёт
малые доли от ложной сходимости по абсолютной дельте.

### 6.4. Критерий изменения TPD

Предложение: **sigma_tpd = 1e−12**:
`|TPD^{(k+1)} − TPD^{(k)}| <= 1e−12` при масштабе суммируемых
вкладов O(1). Критерий контролирует стагнацию СУММЫ (в дополнение к
6.1/6.3), а не заменяет стационарность: попытка считается
сошедшейся только при выполнении 6.1 И 6.3; 6.4 — дополнительный
стоп-сигнал, не дающий права на verdict без 6.1.

### 6.5. Отрицательный TPD threshold

Распространённый порог −1e−8 НЕ копируется. Предложение:
**TPD_negative_threshold = −1e−10**. Обоснование от точности
НАШЕГО evaluator:

- численный шум одного вычисления TPD: форма вклада
  (разность lnPhi первой, устойчивый ln(w/z), Neumaier-сумма)
  вносит ошибку << 1e−15 при вкладах O(1); собственная точность
  PR lnPhi (кубические корни, коэффициенты смеси) даёт полную
  погрешность одного TPD консервативно <= ~1e−13 относительно
  масштаба суммы |вкладов|;
- порог −1e−10 на ТРИ порядка выше этой консервативной оценки
  шума (не классифицирует шум как неустойчивость) и на два порядка
  чувствительнее −1e−8 (не пропускает умеренную, но реальную
  неустойчивость ~ −1e−9, которую внешний порог скрыл бы);
- порог применяется ТОЛЬКО к допустимым, корректно вычисленным
  точкам (успех evaluator 4.4.4.4.1) и НЕ применяется к тривиальной
  точке w = z (TPD = ровно +0 там, где нестабильность не ищется);
- порог — константа будущего модуля с комментарием-обоснованием;
  её изменение требует пересчёта регрессионных тестов §8.

### 6.6. Семантика результатов (имена согласованы с SCOPE_NOTE 4.4.4.4.1)

- **`unstable_detected`** — найдена ДОПУСТИМАЯ корректно
  вычисленная точка (успех evaluator, носитель ⊆ supp(z), сумма в
  допуске) с TPD <= TPD_negative_threshold. Одного такого значения
  достаточно: отрицательное TPD допустимой точки — достаточное
  свидетельство неустойчивости feed-фазы в рамках PR-модели;
  доказывать глобальный минимум НЕ требуется. Результат сохраняет
  точку, её ветвь, TPD, вклады, попытку-источник.
- **`no_instability_found_within_search`** — ВСЕ обязательные
  попытки (старты × ветви × грани в пределах выполненного
  перечисления) завершились корректно (сошлись или честно
  исчерпали бюджет без numerical_failure), и значимого
  отрицательного TPD в пределах РЕАЛЬНО выполненного поиска не
  обнаружено. Это НЕ доказательство глобальной устойчивости:
  конечный multi-start не гарантирует полноты; формулировка
  описывает только выполненный поиск.
- **`indeterminate`** — сходимость, численная точность,
  допустимость ветви, данные или полнота предусмотренного поиска
  не позволяют сделать даже ограниченный отрицательный вывод:
  numerical_failure хотя бы одной обязательной попытки,
  недопустимая/отклонённая политикой ветвь, исчерпание бюджета
  перечисления граней при s > 5, неконечные значения.

Статус `stable` НЕ выдаётся ни при каких условиях. Математическая
глобальная полнота конечного multi-start НЕ утверждается. Эти же
имена перечислены в PR_TANGENT_PLANE_DISTANCE_SCOPE_NOTE (границы
4.4.4.4.1), где зафиксировано, что сам evaluator их не выдаёт:
поисковые заключения — предмет 4.4.4.4.2.

## 7. API и тест-план (предложение контрактов)

### 7.1. Вход (TypeScript-предложение)

interface PrTangentPlaneDistanceSearchInput {

  /** компонентные входы 4.4.4.3 — те же, что дали feed (для trial-пересчётов и Wilson). */
  components: PengRobinsonMixtureComponentInput[];
  /** те же пары kij, что в feed-расчёте. */

  /** T/P/evidencePolicy берутся из feed и побитово сверяются. */

### 7.2. Результат по попытке

```ts
type PrTpdSearchAttemptOutcome =
  | 'converged'        // выполнены 6.1 и 6.3
  | 'max_iterations'   // бюджет 6.2 исчерпан без сходимости
  | 'numerical_failure'// evaluator/PR отказ
  | 'invalid_start';   // старт не удовлетворяет контракту

interface PrTpdSearchAttempt {
  startId: string;              // 'feed' | 'wilson_light' | 'wilson_heavy' | 'uniform' | 'pair_i_j'
  support: string[];            // обследованное подмножество supp(z) (грань)
  root: 'vapor' | 'liquid';    // ветвь пробной фазы
  singleRootDeduplicated: boolean;
  startComposition: number[];
  outcome: PrTpdSearchAttemptOutcome;
  iterations: number;          // фактическое число SS-обновлений
  stationarityResidual: number | null; // 6.1 на финальной точке
  finalComposition: number[] | null;
  tpd: number | null;          // скаляр 4.4.4.4.1 финальной точки
  tpdContributions: { component: string; contribution: number }[] | null;
  failureReason?: string;      // код/сообщение отказа при outcome != converged
}

interface PrTangentPlaneDistanceSearchResultSuccess {
  status: 'success';
  temperatureK: number;        // побитово из feed
  pressurePa: number;
  evidencePolicy: string;
  feedComposition: number[];
  feedRoot: 'vapor' | 'liquid';
  attempts: PrTpdSearchAttempt[];      // канонический порядок: старт → грань → ветвь
  bestTpd: number | null;              // минимальный TPD по converged-попыткам (кроме тривиальной)
  bestAttemptIndex: number | null;
  searchVerdict:
    | 'unstable_detected'
    | 'no_instability_found_within_search'
    | 'indeterminate';
  negativeThreshold: number;          // 6.5, зафиксирован в результате для прозрачности
  faceEnumeration: 'complete' | 'partial';
  notes: string[];                     // single_physical_root, границы поиска и пр.
}
```

Отказы всего поиска — существующие коды: `invalid_input`,
`incompatible_state`, `support_violation`, `numerical_failure`
(например, feed-состояние не success, компонентные входы не
совместимы с feed, носитель пуст). Verdict-имена — только
перечисленные в 6.6; поля `stable` нет и не появляется.

### 7.3. Тест-план (обязательный минимум)

Каждый тест фиксирует И семантику, И численные значения против
НЕЗАВИСИМЫХ оракулов (прямое вычисление формулы в тесте), никогда —
против самого производственного TPD-вычислителя.

1. **Идеальный газ / KL-предел**: lnPhi = 0; TPD(w; z) = KL(w||z) >= 0
   с минимумом в w = z; все попытки сходятся к TPD = 0 (тривиальная
   точка); verdict `no_instability_found_within_search`.
2. **Синтетический надёжно отрицательный TPD**: синтетическая
   конфигурация (НЕ из каталога, НЕ заявляемая как физическая) с
   TPD ~ −1e−3 в точке, куда сходится хотя бы один старт; verdict
   `unstable_detected`, bestTpd <= порога. Тест ДОКУМЕНТИРОВАН как
   синтетический: он проверяет механику поиска, НЕ
   экспериментальную валидацию EOS.
3. **Чувствительность к начальным приближениям**: синтетический
   случай с двумя стационарными точками (разные знаки TPD): лёгкий
   и тяжёлый старты сходятся к РАЗНЫМ точкам; тест фиксирует, что
   один старт недостаточен (без второго старта verdict был бы
   ложным), и что попытки сохраняют обе точки.
4. **Single-root и two-root**: two-root — обе ветви выполняются
   независимо (root в попытках различен); single-root (кубика с
   одним физическим корнем) — попытки с обеими метками
   singleRootDeduplicated, считаются одной, `single_physical_root`
   в notes.
5. **Перестановка компонентов**: перестановка входных массивов не
   меняет verdict, bestTpd и tpd побитово (канонический порядок
   итерации).
6. **Нулевые доли и границы носителя**: z_i = 0 запрещает w_i > 0
   (`support_violation`, пробная попытка не создаётся); минимум на
   грани 2-компонентной смеси обнаруживается граничным поиском;
   faceEnumeration корректен.
7. **Неудачная сходимость / лимит итераций**: попытка с зажатым
   бюджетом → `max_iterations`, verdict не становится
   `no_instability_found_within_search`, если обязательная попытка
   не сошлась (→ `indeterminate`).
8. **Пограничное значение около порога**: TPD около −1e−10
   (регрессионная фиксация порога): значения ниже порога — unstable,
   выше — не классифицируются как unstable; классификация по
   порогу, не по знаку.
9. **Неконечные значения**: NaN/Infinity lnPhi в PR-пересчёте →
   `numerical_failure` попытки → `indeterminate` поиска; NaN не
   попадает в tpd/bestTpd/searchVerdict.
10. **Повторяемость**: два вызова с одним входом — побитово равные
    результаты (все поля).

Дополнительно: отсутствие поля `stable` (фиксация множества
verdict-имён); нарушение суммы состава старта → `invalid_start`;
бюджет: фиксация фактического числа PR-пересчётов <= лимита.

## 8. Научные ограничения

1. CO2–N2 с kij = −0.017 — МОДЕЛЬНЫЙ сценарий с ограниченной
   экспериментальной опорой: статус `PARTIALLY_VERIFIED`,
   применимость 228.15–273.15 K; по Table A4 Okoro 2024 original
   PR/vdW отклоняется на 35.14%/21.31% — пара НЕ является
   количественно подтверждённой модельной системой. TPD-поиск на
   этой паре НЕ превращает её в экспериментально валидированную
   систему: любые поисковые заключения ограничены выбранной
   PR-моделью и принятыми данными.
2. НЕ импортируются: KIDA BIP, adjusted/New BIP Okoro (−0.01322 по
   Table 1; квадратичная температурная зависимость; точная
   температурная атрибуция скаляра одной Table 1 не
   устанавливается), новые EOS-значения. Evidence-статусы НЕ
   повышаются.
3. Поиск ограничен парами kij, доступными в каталоге
   (остальные пары — отказ `missing_binary_interaction`,
   kij = 0 НЕ подставляется), и применимостью kij по температуре
   (`binary_interaction_applicability`).
4. Синтетические тесты (§7.3) — проверка механики поиска, НЕ
   экспериментальная валидация EOS и НЕ свидетельство о поведении
   реальных CO2–N2.
5. Поисковые заключения `unstable_detected` /
   `no_instability_found_within_search` / `indeterminate` —
   statements о PR-модели с принятыми данными в выполненном
   поиске; глобальная устойчивость не доказывается никогда.
