## 1. Математический контракт

### 1.1. Исходная TPD-функция

Исходная TPD-функция (обозначение Michelsen):

```
g(w; z) = SUM_{i: w_i > 0} w_i [ ln w_i + lnPhi_i(w) − h_i ],
h_i = ln z_i + lnPhi_i(z)
```

через h_i она эквивалентна формуле Stage 4.4.4.4.1:
w_i [ln(w_i/z_i) + lnPhi_i(w) − lnPhi_i(z)] — безразмерная dG/RT:
расстояние от касательной плоскости к поверхности энергии Гиббса
смеси в точке feed z. Значение и вклады вычисляет существующий
evaluator 4.4.4.4.1 (контракт НЕ меняется: скаляр + вклады,
компенсированная сумма Neumaier, устойчивый ln(w/z), fail-closed
коды). Поиск 4.4.4.4.2 — ОРКЕСТРАЦИЯ вокруг этого evaluator:
генерация пробных точек, пересчёт PR-состояний пробной фазы,
итерации к стационарным точкам, классификация.

### 1.2. Допустимое пространство составов

- носитель feed: supp(z) = { i : z_i > 0 };
- допустимый пробный состав: w_i >= 0, SUM w_i = 1 (в существующем
  допуске суммы состава, БЕЗ нормализации), и
  **supp(w) ⊆ supp(z)**: положительная trial-доля при z_i = 0
  запрещена — это уже структурный отказ `support_violation`
  контракта 4.4.4.4.1 (0·ln 0 не вычисляется, ln(w_i/z_i) при
  z_i = 0 не определён);
- никакой epsilon-подмены нулевых долей и никакой молчаливой
  нормализации состава: нарушенная сумма — отказ, а не исправление.

### 1.3. Стационарное условие и вспомогательная функция Michelsen

**Стационарное условие на нормированном составе.** Внутренняя
стационарная точка g по допустимым w (все активные w_i > 0 на
рассматриваемом носителе) удовлетворяет

```
ln w_i + lnPhi_i(w) − h_i = k   (для всех активных i)
```

где k — ОДНА И ТА ЖЕ константа для всех активных компонентов
(множитель Лагранжа ограничения нормировки). Для нормированного
состава значение функции в стационарной точке равно этой константе:

```
g_sp = SUM_i w_i [ln w_i + lnPhi_i(w) − h_i] = k · SUM_i w_i = k
```

**Ненормированные псевдомольные переменные Michelsen.** Вводятся
через константу стационарной точки:

```
Y_i = exp(−k) · w_i
```

Тогда стационарное условие принимает нулевую форму

```
ln Y_i + lnPhi_i(w) − h_i = 0   (для всех активных i)
```

а нормировка восстанавливается делением:

```
w_i = Y_i / SUM_j Y_j
```

**Вспомогательная функция Michelsen** (в терминах Y, при
w = Y/ΣY):

```
g*(Y) = 1 + SUM_i Y_i [ ln Y_i + lnPhi_i(w) − h_i − 1 ]
```

В стационарной точке нулю равна НЕ вся скобка: нулевую форму
стационарного условия даёт её часть ln Y_i + lnPhi_i(w) − h_i = 0,
а вся скобка [ ln Y_i + lnPhi_i(w) − h_i − 1 ] равна **−1**,
поэтому

```
g*_sp = 1 − SUM_i Y_i = 1 − exp(−k) = 1 − exp(−g_sp)
```

**Соответствие g* и g.** g* и g имеют соответствующие стационарные
точки (Y* ↔ w* = Y*/ΣY*) и ОДИНАКОВЫЙ ЗНАК стационарных значений:
exp монотонен, поэтому g_sp < 0 ⟺ exp(−g_sp) > 1 ⟺ g*_sp < 0, и
аналогично для g_sp > 0. Но это РАЗНЫЕ функции: g*(Y) —
ВСПОМОГАТЕЛЬНАЯ функция для итераций, НЕ исходная TPD; её значения
вне стационарных точек не являются dG/RT, а стационарные значения
связаны с g нелинейно (1 − exp(−g_sp)). НЕ называть g*(Y) исходной
TPD-функцией; для классификации используется ЗНАК (любой из двух
эквивалентных способов), а сравнение величин — только в терминах g.

**Тривиальная стационарная точка.** w = z даёт k = 0 и Y_i = z_i;
g = g* = 0 — НО только для ИДЕНТИЧНОГО состояния (та же ветвь корня
PR, см. §1.4/§2.1): точный +0 тривиального случая относится к
идентичным feed/trial-состояниям.

**Утверждение о линейности удалено.** Прежняя формулировка
ревизии называла целевую функцию в ненормированных переменных
«линейной по W» — это неверно (члены ln W_i нелинейны) и удалена.

**Обновление successive substitution.** Из нулевой формы
стационарного условия:

```
ln Y_i^(k+1) = h_i − lnPhi_i( w^(k) ),   w^(k) = Y^(k) / SUM_j Y_j^(k)
```

PR-состояние (lnPhi_i) пересчитывается по НОРМИРОВАННОМУ составу
w^(k); итерационные переменные Y остаются НЕнормированными
(ΣY — оценка «мольного количества» пробной фазы; 1 − ΣY = g*
в стационарной точке). Оба уровня разделены явно: PR и evaluator
получают составы, итерации ведутся в Y. Тривиальный старт w = z
(на ветви feed) — неподвижная точка SS-обновления
(ln Y^(1) = ln z + lnPhi(z) − lnPhi(z) = ln z), что используется
как smoke-проверка итерационной механики (§2.1).

Граничные стационарные точки лежат на гранях носителя: на
подмножестве активных компонентов условие выполняется с теми же
свойствами, поиск на грани — §5.

### 1.4. Роль ветви корня PR

lnPhi_i(w) берётся из PR-состояния пробной фазы с выбранной ветвью
корня: `vapor` — наибольший физический корень, `liquid` — наименьший
(контракт 4.4.4.3: selectedRoot = physical[last] для vapor,
physical[0] для liquid). Ветвь — часть моделирования ПРОБНОЙ фазы;
выбор ветви сам по себе НЕ является ни доказательством существования
такой фазы, ни доказательством устойчивости/неустойчивости.

**Идентичность состояния требует одну и ту же ветвь.** Точный
TPD = +0 тривиального случая относится к идентичным feed/trial-
состояниям: побитово одинаковые T/P/evidencePolicy/a_i/b_i/kij И
одна и та же ветвь корня PR. Одинаковый состав w = z, вычисленный
на ДРУГОЙ ветви корня, — ДРУГОЕ состояние: корень кубики и lnPhi
могут различаться, TPD НЕ обязан быть нулём и обязан вычисляться
штатно. Такая точка — самостоятельная допустимая пробная точка: она
НЕ исключается из проверки отрицательности на основании равенства
составов и НЕ получает автоматически статус тривиального
TPD(z; z) = +0 (старт feed_alternative_branch, §2.1).

### 1.5. Стационарная точка ≠ доказанный глобальный минимум

Локальные методы (successive substitution, safeguarded Newton)
сходятся к ОДНОЙ стационарной точке на начальное приближение;
TPD-функция может иметь несколько стационарных точек, а локальный
минимум может не быть глобальным. Поэтому:

- надёжно отрицательное TPD (класс C1, §6.6) в любой ДОПУСТИМОЙ
  корректно вычисленной ПОСЕЩЁННОЙ точке (не только в сошедшейся
  стационарной) — ДОСТАТОЧНОЕ свидетельство неустойчивости
  feed-фазы в рамках PR-модели: глобальный минимум искать не
  требуется, он не выше найденного значения; сходимость породившей
  попытки НЕ требуется (§6.6);
- неотрицательное TPD во всех НАЙДЕННЫХ точках НЕ доказывает
  глобальной устойчивости: конечный набор стартов и итераций не
  гарантирует полноты (см. §6.6, семантика
  `no_instability_found_within_search`).

   состояния. Включается как базовая попытка (smoke-проверка
   сходимости итерационной механики), но тривиальный результат не
   считается «найденным нетривиальным минимумом» и не может дать
   `unstable_detected`.
2. **`feed_alternative_branch`** — w = z на АЛЬТЕРНАТИВНОЙ ветви
   корня PR (если `hasDistinctBranches`; при единственном
   физическом корне старт не создаётся — ветвь одна, см. §3). Тот
   же состав — ДРУГОЕ состояние: вычисляется штатно через PR на
   альтернативной ветви и оценивается evaluator'ом; TPD НЕ
   предполагается нулём (§1.4) и НЕ исключается из проверки
   отрицательности.
3. **`wilson_vapor_like`** — пароподобная пробная фаза:
   ненормированный старт Y^(0) = z·K, т.е. ln Y_i^(0) = ln z_i +
   ln K_i (обогащение лёгкими компонентами; масштаб Y^(0)
   сохраняется, нормировка w^(0) — §2.3).
4. **`wilson_liquid_like`** — жидкоподобная пробная фаза:
   ненормированный старт Y^(0) = z/K, т.е. ln Y_i^(0) = ln z_i −
   ln K_i (обеднение лёгкими компонентами; масштаб Y^(0)
   сохраняется, нормировка w^(0) — §2.3).
5. **`uniform`** — равномерный состав по носителю: w_i = 1/s.
6. **`pair_{i,j}`** — парные составы w_i = w_j = 0.5 для каждой
   упорядоченной пары i < j из supp(z) (O(s^2) точек,
   детерминированный порядок).

**Конвенция направлений Wilson (исправление ревизии).** Прежние
имена `wilson_light` / `wilson_heavy` допускали двоякое чтение
(метка пробной фазы или предположение о feed) и переименованы.
Метки описывают САМУ ПРОБНУЮ ФАЗУ, а не предположение о feed. По
двустороннему уравнению Michelsen (см. §0, пункт 5): жидкоподобный
feed → пароподобная пробная фаза Y_i = z_i·K_i; пароподобный feed →
жидкоподобная пробная фаза Y_i = z_i/K_i. Wilson K_i > 1 у лёгких
компонентов, поэтому z·K обогащает состав лёгкими компонентами
(пароподобное НАПРАВЛЕНИЕ пробной фазы), z/K — обедняет
(жидкоподобное направление). Документация GEOS строит те же два
направления по Wilson K-values, но в СОБСТВЕННОЙ номенклатуре и в
ОБРАТНОМ словесном порядке относительно нашей конвенции: «lighter
trial mixture» y_i = z_i/K_i (наш `wilson_liquid_like`) и «heavier
trial mixture» y_i = z_i·K_i (наш `wilson_vapor_like`). Словесная
маркировка GEOS НЕ переносится в наш API: имена light/heavy НЕ
используются ни в API, ни в именах стартов — только физически
однозначные vapor_like/liquid_like. Оба направления обязательны;
литература прямо отмечает зависимость результата stability
analysis от начальных K-values (§0, пункт 4).

### 2.2. Wilson K-values: доступность данных (проверено)

Корреляция Wilson (1969):

```
K_i = (Pc_i / P) · exp( 5.373 · (1 + omega_i) · (1 − Tc_i / T) )
```

Требуемые Tc_i, Pc_i, omega_i УЖЕ доступны в контракте 4.4.4.3:
`PengRobinsonMixtureComponentInput` содержит `criticalTemperatureK`,
`criticalPressurePa`, `acentricFactor` (вместе с moleFraction,
per-field evidence, crossChecks, limitations) — это те же
валидированные каталогом (4.4.4.1) параметры, которые evidencePolicy
уже приняла при расчёте feed-состояния. Wilson starts НЕ требуют
нового provenance и НЕ вводят новых чисел: они переиспользуют
принятые параметры. Если политика отклонила параметры какого-то
компонента, PR-расчёт feed невозможен и поиск не начинается вовсе
(отказ раньше). Никакие параметры не восстанавливаются и не
выдумываются. Благодаря единому источнику истины входов (§4.3)
Wilson starts структурно НЕ могут использовать параметры, не
соответствующие feed.

### 2.3. Ненормированный масштаб Y и log-space построение стартов

Вектор Michelsen Y — НЕнормированные псевдомольные количества
(§1.3); АБСОЛЮТНЫЙ масштаб Wilson-старта несёт информацию и НЕ
должен теряться при формировании старта. Всё построение ведётся
сразу в логарифмах, БЕЗ промежуточного exp для K:

```
ln K_i = ln(Pc_i) − ln(P) + 5.373 · (1 + omega_i) · (1 − Tc_i / T)
```

исходное состояние итерационной переменной:

- `wilson_vapor_like`: ln Y_i^(0) = ln z_i + ln K_i
  (ненормированный вектор z·K);
- `wilson_liquid_like`: ln Y_i^(0) = ln z_i − ln K_i
  (ненормированный вектор z/K);

нормировка — только для передачи в PR/evaluator:

```
ln w_i^(0) = ln Y_i^(0) − logsumexp( ln Y^(0) )
```

**ТРИ ОТДЕЛЬНЫХ правила** (обязательны для реализации):

1. **ln Y^(0) сохраняется как исходное состояние итерационной
   переменной попытки**: абсолютный масштаб z·K или z/K (ΣY^(0) ≠ 1
   в общем случае) — начальная оценка «мольного количества» пробной
   фазы (§1.3) и передаётся в SS-итерации (§2.4);
2. **в PR-пересчёт и TPD-evaluator передаётся ТОЛЬКО нормированный
   w^(0) = Y^(0)/ΣY^(0)** (и нормированные составы всех
   последующих итераций);
3. **successive substitution обновляет НЕнормированный Y**
   (§1.3: ln Y_i^(k+1) = h_i − lnPhi_i(w^(k))), а не нормированный
   w.

**ЗАПРЕЩЕНО**: сначала нормализовать Wilson Y (w = Y/ΣY) и затем
использовать Y = w как начальное состояние итераций — это теряет
исходный масштаб z_i·K_i или z_i/K_i и даёт ДРУГОЕ начальное
состояние (ΣY^(0) = 1); итерации обязаны стартовать с сохранённого
ln Y^(0).

**Масштаб Y^(0) остальных стартов** (единообразно и
детерминированно): для стартов, задаваемых только составом (`feed`,
`feed_alternative_branch`, `uniform`, `pair_{i,j}`, feed-restricted
на гранях §5), принимается Y^(0) = w^(0), ΣY^(0) = 1. Для `feed`
это согласовано с тривиальной неподвижной точкой SS (§1.3:
ln Y^(1) = ln z).

Это исключает и переполнение/исчезновение при экстремальных K, и
epsilon-подмену: члены с z_i = 0 в носитель не входят
(структурно, §1.2), z_i > 0 гарантирует конечный ln z_i.
Компоненты с выродившимся (ноль после нормировки в double) w_i
просто не входят в пробный носитель — support-контракт evaluator
обрабатывает это штатно.

### 2.4. Итерации successive substitution и оценка траектории

Каждая попытка стартует с сохранённого ln Y^(0) (§2.3) и ведёт
итерации по §1.3: нормировка Y → w, PR-пересчёт по w (та же ветвь
корня, те же T/P/kij, §4.2), SS-обновление в НЕнормированном Y.
**Каждая допустимая посещённая точка оценивается существующим
TPD-evaluator'ом** (feed-состояние против текущей trial-точки) —
включая точки, вычисленные в fallback, численном якобиане и
line-search (§2.5): точка, отвергнутая как оптимизационный шаг,
остаётся допустимой ПРОБНОЙ точкой и участвует в bestVisitedPoint
и проверке отрицательности наравне с SS-точками. Попытка
накапливает:

- минимальный TPD, встреченный за ВСЮ траекторию попытки
  (bestVisitedPoint), с составом соответствующей точки, ветвью
  корня, номером итерации, вкладами компонентов, идентификатором
  старта и подмножеством носителя;
- финальную стационарную точку (finalStationaryPoint) — только если
  попытка сошлась (§6.1/§6.3).

Разделение обязательно: bestVisitedPoint и finalStationaryPoint —
РАЗНЫЕ записи; минимум траектории может достигаться в промежуточной
итерации, а не в финальной точке. Если попытка позже НЕ сошлась,
уже обнаруженные отрицательные значения НЕ теряются: они остаются
в bestVisitedPoint попытки и в глобальном bestVisitedTpd поиска
(§7.2) и могут давать `unstable_detected` (§6.6).

### 2.5. Safeguarded fallback (требование, не реализация)

При исчерпании SS-бюджета N_SS_max (§6.2) без выполнения критериев
§6.1–6.4 попытка ПЕРЕКЛЮЧАЕТСЯ на ЛОКАЛЬНЫЙ safeguarded fallback в
переменных ln Y (позитивность гарантирована параметризацией):
quasi-Newton (BFGS) или safeguarded Newton с ЧИСЛЕННЫМ якобианом
конечными разностями по ln Y. Бюджет задан ЯВНО и проверяемо
(устраняет прежнее противоречие «fallback после исчерпания бюджета
итераций, но в пределах того же бюджета»):

- **N_SS_max** — максимум SS-обновлений на попытку (§6.2);
- **N_fallback_max** — ОТДЕЛЬНЫЙ резерв fallback-шагов на попытку
  (§6.2);
- **N_total_max** — общий предел итераций попытки:
  N_SS_max + N_fallback_max <= N_total_max;
- переключение на fallback — ТОЛЬКО после исчерпания N_SS_max;
  остановка — после исчерпания N_fallback_max; превышение
  N_total_max и maxPrEvaluations (§4.4) невозможно по построению и
  проверяется тестами (§7.3);
- на один fallback-шаг: численный якобиан — до |S| дополнительных
  PR-пересчётов (аналитические производные lnPhi по составу в
  проекте НЕ реализованы; интерфейс якобиана — предмет отдельного
  будущего этапа) и line-search с явным максимумом L_line_max
  кандидатных PR-пересчётов на шаг;
- отказные (fail-closed) PR-вызовы fallback СЧИТАЮТСЯ в бюджет
  наравне с успешными (§4.4);
- любая допустимая точка, реально вычисленная в fallback, численном
  якобиане или line-search, проходит TPD-evaluator и участвует в
  bestVisitedPoint и проверке отрицательности (§2.4); точка,
  отвергнутая как оптимизационный шаг, НЕ теряется как пробная
  точка; неудавшийся fallback — та же классификация (§6.6), что и
  неудавшийся SS;
- fallback НЕ меняет семантику результатов;
- глобальные методы (туннелирование, интервальный анализ,
  стохастика) в 4.4.4.4.2 НЕ предлагаются — вне бюджета этапа;
  невозможность гарантировать глобальный минимум закрыта семантикой
  `no_instability_found_within_search`, а не алгоритмом.

## 3. Ветви корня PR

1. **Уникальные корни.** PR-кубика смеси может иметь до двух
   физических корней (контракт 4.4.4.3: `physicalRoots`,
   `distinctPhysicalRootCount`, `hasDistinctBranches = length >= 2`).
   Каждая попытка привязана к ОДНОМУ уникальному физическому корню
   пробной фазы.
2. **Однозначный контракт единственного корня.** При
   `hasDistinctBranches === false` (единственный физический корень)
   НЕ запускаются две одинаковые PR-попытки под метками vapor/liquid
   и НЕ дедуплицируются постфактум. Исполняется ОДНА фактическая
   PR-попытка на уникальный корень; запись попытки хранит:
   - `logicalLabels: ['vapor', 'liquid']` — обе логические метки
     ссылаются на один и тот же корень;
   - `selectedRoot` — фактически выбранный физический корень
     кубики (Z);
   - `singlePhysicalRoot: true`.
   Предупреждение `single_physical_root` (4.4.4.3) сохраняется в
   notes результата. Дублирования результата, искусственного
   двойного счёта попыток и двойного расхода бюджета НЕТ.
3. **Два различных корня.** При `hasDistinctBranches === true`
   попытки по обеим ветвям выполняются НЕЗАВИСИМО
   (logicalLabels = ['vapor'] и ['liquid'] соответственно,
   разные selectedRoot), каждая — отдельная попытка со своим
   траекториями и бюджетом.
4. **Feed-ветвь** фиксирована входом вызывающего кода
   (`request.root`, §7.1) и не перебирается; старт
   `feed_alternative_branch` (§2.1) покрывает альтернативную ветвь
   тем же составом z (при двух корнях).
5. Выбор ветви — моделирование пробной фазы, НЕ доказательство её
   физического существования и НЕ доказательство устойчивости.

## 4. Архитектура Core/Data (проверено по фактическому коду)

### 4.1. Доступные данные (проверено)

Из `PengRobinsonMixtureSuccess` (4.4.4.3) доступны: `a_i`, `b_i`,
`S_i`, `lnPhi_i`, `phi_i`, `f_i` по компонентам;
`binaryInteractionsUsed` (значение kij, evidence,
applicabilityRangeK по использованным парам);
`physicalRoots`, `distinctPhysicalRootCount`, `hasDistinctBranches`,
`selectedRoot`, `Z`; предупреждения (включая
`single_physical_root`, `h2o_classical_pr_limitations`). Из
Data-фасада (`computePengRobinsonMixtureFromCatalog`) дополнительно
доступны provenance-скаляры `componentParameters` /
`binaryInteractionParameters`. Контракт применимости kij по
температуре нарушать нельзя: выход пары за `applicabilityRangeK` —
отказ `binary_interaction_applicability`, kij = 0 НЕ
подставляется.

### 4.2. Пересчёт PR для нового trial-состава

Пересчёт PR-состояния пробной фазы при неизменных T/P и тех же
параметрах взаимодействия — тот же вызов `computePengRobinsonMixture`
(4.4.4.3) с ТЕМИ ЖЕ `components` (те же идентификаторы, Tc/Pc/omega,
evidence, crossChecks, limitations; меняются только moleFraction)
и `binaryInteractions`, что и для feed, и request
`{ temperatureK, pressurePa, root, evidencePolicy }`. Provenance НЕ
нарушается: параметры те же, уже принятые политикой; новых чисел не
возникает; evidencePolicy применяется к каждому пересчёту
одинаково. TPD-evaluator 4.4.4.4.1 получает уже вычисленные
состояния и побитово сверяет T/P/evidencePolicy/a_i/b_i/kij-пары —
контракт 4.4.4.4.1 остаётся без изменений.

### 4.3. Единый источник истины входов (корректирующая ревизия)

Прежняя схема API (отдельно `feed: PengRobinsonMixtureSuccess`,
отдельно `components`, отдельно `binaryInteractions`) отвергнута:
`PengRobinsonMixtureSuccess` НЕ содержит полного исходного набора
(Tc/Pc/omega с per-field evidence, crossChecks, limitations),
поэтому независимые массивы могли — случайно или намеренно — не
соответствовать параметрам, из которых был получен feed.

Выбран проверяемый единый источник истины:

- **Core-search принимает ПОЛНЫЕ исходные `PengRobinsonMixtureInputs`
  ({components — включая moleFraction feed-состава, evidence,
  crossChecks, limitations — и binaryInteractions}) и
  `PengRobinsonMixtureRequest` {temperatureK, pressurePa,
  root = feedRoot, evidencePolicy} и САМ пересчитывает авторитетное
  feed-состояние через `computePengRobinsonMixture` до начала
  поиска.** Согласованность обеспечивается by construction: нет
  второго источника параметров, который мог бы разойтись; Wilson
  starts могут использовать ТОЛЬКО те же компонентные входы
  (§2.2); trial-пересчёты — копии тех же inputs с изменённым
  moleFraction (§4.2).
- Альтернатива (передавать и feed success, и полные inputs, затем
  пересчитывать feed из inputs и сверять с переданным до поиска)
  отвергнута: побитовая сверка полного success-объекта хрупка и
  дороже, чем построение feed из единого входа, и оставляет
  два источника истины на входе.
- Контракт существующего TPD-evaluator НЕ меняется: он по-прежнему
  получает ДВА уже вычисленных состояния (feed и trial), которые
  готовит оркестратор (§4.2); любое изменение его контракта —
  отдельное обоснование и отдельный этап.

### 4.4. Детерминированность и вычислительный бюджет

- Поиск полностью детерминирован: фиксированный порядок
  подмножеств, стартов и уникальных корней; никакого рандома;
  повторный вызов с тем же входом даёт побитово тот же результат.
- **faceCount** — число непустых СОБСТВЕННЫХ подмножеств носителя
  (граней): 2^s − 2, где s = |supp(z)|; вместе с полным носителем
  поиск покрывает 2^s − 1 подмножеств. faceCount — НЕ число
  итерационных запусков: 30 граней при s = 5 — это СТРУКТУРА
  перебора, а не «30 попыток».
- **attemptCount** = Σ по подмножествам S поиска
  (уникальные старты на S после дедупликации §5) × (число
  уникальных физических корней на S, ≤ 2; 1 при single root).
- **Единое правило подсчёта PR-вызовов**: считаются ВСЕ фактические
  вызовы `computePengRobinsonMixture` поиска, включая
  завершившиеся отказом (fail-closed отказы расходуют бюджет
  наравне с успешными); переиспользование уже вычисленного
  состояния (например, авторитетного feed-состояния для старта
  `feed` на ветви feed) НЕ считается новым вызовом.
- **maxPrEvaluations** = 1 (авторитетный feed PR-расчёт) +
  Σ по попыткам a = (грань, старт, уникальный корень):
  [ init_a + N_SS_max + N_fallback_max · ( |S_a| + L_line_max ) ],
  где init_a = 0 при переиспользовании feed-состояния (старт
  `feed` на ветви feed), иначе 1 (начальный PR-расчёт стартовой
  точки); N_SS_max — SS-обновления (§6.2), N_fallback_max — резерв
  fallback-шагов (§2.5, §6.2), |S_a| — численный якобиан,
  L_line_max — максимум line-search-кандидатов на fallback-шаг
  (§2.5). Формула детерминирована по входу и проверяема тестами
  (§7.3).
- Результат ОБЯЗАН возвращать фактические счётчики: faceCount,
  attemptCount, prEvaluations и maxPrEvaluations (§7.2); тесты
  фиксируют prEvaluations <= maxPrEvaluations (§7.3).
- Для каталога (s <= 5) полное перечисление граней стоит
  faceCount <= 30 и attemptCount, вычисляемый по формуле выше
  (после дедупликации — меньше); точные числа выводятся из формул
  в момент исполнения и не заявляются константами.

## 5. Границы симплекса

1. **Внутренний поиск**: старты §2.1 на полном носителе supp(z);
   SS-итерации §1.3 сохраняют носитель (ln Y_i конечен при z_i > 0).
2. **Грани носителя**: минимум TPD может лежать на грани (часть
   W_i = 0). Стратегия: тот же поиск (старты + SS) выполняется на
   каждом собственном непустом подмножестве носителя. Построение
   стартов на грани S ⊆ supp(z):
   - feed-restricted: z|_S, нормированный по S (Y^(0) = w^(0),
     ΣY^(0) = 1, §2.3);
   - wilson_vapor_like / wilson_liquid_like: ln Y^(0) =
     ln z|_S ± ln K (ненормированный масштаб сохраняется, §2.3),
     нормировка по S — только для w^(0);
   - uniform: 1/|S| на S (Y^(0) = w^(0));
   - pair_{i,j} внутри S (Y^(0) = w^(0)).
   **Правила дедупликации стартов**: старты с побитово равными
   стартовыми векторами состава, на том же подмножестве и против
   того же уникального корня исполняются ОДИН раз (каноническая
   сериализация как ключ дедупликации). Примеры: |S| = 1 — все
   старты совпадают с единственной вершиной (1 запуск);
   |S| = 2 — uniform совпадает с pair (не удваивает бюджет).
   Перечисление граней: полное при s <= 5 (каталог — потолок,
   faceCount <= 30); при s > 5 — детерминированная выборка граней
   (например, все грани размера s−1 и s−2) и ЧЕСТНАЯ маркировка
   `faceEnumeration: 'partial'` с перечнем обследованных
   подмножеств.
3. **Вырождение на границе итераций**: если SS-итерация загоняет
   компонент к нулю (w_i → 0 в double), попытка завершается на
   достигнутой точке, и старт повторяется на соответствующей грани —
   граничный минимум ищется штатным поиском грани, а не
   «дотяжкой» нуля.
4. **Честная маркировка**: результат всегда содержит
   `faceEnumeration` ('complete' | 'partial') и список обследованных
   подмножеств. Поиск только по внутренним точкам НЕ выдаёт
   формулировку, эквивалентную доказательству глобальной
   устойчивости: `no_instability_found_within_search` описывает
   РЕАЛЬНО выполненный поиск и только его.

## 6. Сходимость и численная классификация

### 6.1. Stationarity tolerance

Невязка стационарности на финальной нормированной точке попытки
(все активные i, §1.3):

```
b_i = ln w_i + lnPhi_i(w) − h_i,   k̂ = SUM_i w_i · b_i (= g),
r_stat = max_i | b_i − k̂ |
```

(в стационарной точке все b_i равны одной константе k = g).
Предложение: **sigma_stat = 1e−10**. Обоснование: невязка на 4–6
порядков выше машинного шума итераций (ulp-масштаб lnPhi ~1e-16) и
на несколько порядков ниже любого физически осмысленного масштаба
lnPhi (O(0.1–10)). Значение — инженерный допуск сходимости;
ПОЛНАЯ погрешность TPD — отдельный вопрос §6.5.

### 6.2. Лимиты итераций: бюджет SS и fallback

Предложение (предварительные значения спецификации, §8):

- **N_SS_max = 300** SS-обновлений на попытку (грань × старт ×
  уникальный корень);
- **N_fallback_max = 50** fallback-шагов на попытку — отдельный
  резерв (§2.5);
- **N_total_max = 350**: N_SS_max + N_fallback_max = 350 <=
  N_total_max; переключение на fallback — только после исчерпания
  N_SS_max, остановка — после исчерпания N_fallback_max,
  превышение N_total_max невозможно по построению.

Обоснование N_SS_max: SS сходится линейно; 300 итераций покрывают
и медленные случаи, и остаются дешёвыми в детерминированном
бюджете (§4.4). Литературные лимиты (сотни итераций) подтверждают
порядок величины; точные значения — наши, по бюджету. Бюджет
попытки входит в maxPrEvaluations по формуле §4.4.

### 6.3. Критерий изменения состава

Предложение: **sigma_w = 1e−12** в log-space (переменные Y, §1.3):
`max_i |ln Y_i^(k+1) − ln Y_i^(k)| <= 1e−12`. Состав отслеживается
в логарифмах, поэтому критерий бережёт малые доли от ложной
сходимости по абсолютной дельте.

### 6.4. Критерий изменения TPD

Предложение: **sigma_tpd = 1e−12**:
`|TPD^(k+1) − TPD^(k)| <= 1e−12` при масштабе вкладов O(1).
Критерий контролирует стагнацию СУММЫ; попытка считается
сошедшейся только при выполнении 6.1 И 6.3; 6.4 — дополнительный
стоп-сигнал и НЕ даёт права на заключение без 6.1.

### 6.5. Отрицательный TPD threshold (корректирующая ревизия)

**Статус: ПРЕДВАРИТЕЛЬНОЕ, НЕУТВЕРЖДЁННОЕ предложение.**
`t_neg = −1e−10` — рабочее предварительное значение для тестов и
первой реализации, НЕ научно доказанная граница. Порог −1e−8 из
внешних реализаций НЕ копируется (проигрывает умеренной, но реальной
неустойчивости ~ −1e−9); уверенность в −1e−10 НЕ заявляется.

**Раздельные понятия** (не смешивать):

1. **оценка TPD** — скаляр tpdEstimate существующего evaluator
   4.4.4.4.1 в точке;
2. **оценка численной неопределённости uTPD** — консервативная
   оценка полной ошибки вычисления TPD в точке (источник и статус —
   ниже);
3. **предварительный operational margin t_neg = −1e−10** —
   отдельное предварительное значение «достаточного отрицательного
   запаса», НЕ оценка точности;
4. **знак TPD** классифицируется ТОЛЬКО интервально (§6.6):
   [tpdEstimate − uTPD, tpdEstimate + uTPD].

**Декомпозиция погрешностей** (раздельно, без смешения):

1. вычисление ln(w/z) в evaluator 4.4.4.4.1 — устойчивая форма
   (w===z, log1p, fallback разности логарифмов);
   регрессионно охарактеризована, вносит ошибку много меньше
   1e−15 при вкладах O(1);
2. суммирование вкладов — компенсированная сумма Neumaier;
   регрессионно охарактеризована (малые TPD до ~1e−22 в близких
   составах разрешаются);
3. PR-кубика смеси и выбор физического корня — решатель 4.4.4.2.2
   (DD + dyadic-BigInt-знак) точен в классификации корней, НО
   погрешность корня Z и её влияние на lnPhi вблизи
   вырожденных/почти кратных корней НЕ охарактеризованы
   количественно;
4. вычисление lnPhi — цепочка a_mix, S_i, ln-членов; погрешность
   НЕ охарактеризована количественно глобально;
5. итерационный остаток стационарности — ограничен допуском 6.1
   (1e−10), НЕ нулевой.

Точность арифметики evaluator в отдельных регрессионных тестах НЕ
доказывает глобальную погрешность PR lnPhi и корней кубики вблизи
вырожденных случаев. Прежнее утверждение ревизии о полной ошибке
PR-вычисления TPD «~1e−13» УДАЛЕНО как неподтверждённое измерениями.

**План количественного аудита** (обязателен до утверждения
порога; независимый от реализации поиска):

- высокоточный oracle для PR mixture (прецедент: независимые
  бенчмарки 4.4.4.2.2/4.4.4.3 с mpmath/CoolProp);
- смеси разной размерности (2–5 компонентов: реальный каталог и
  синтетика);
- обычные two-root состояния И режимы около слияния физических
  корней (почти кратные корни кубики);
- составы с долями, близкими к нулю, и сильно неравномерные;
- независимое сравнение итогового TPD и отдельных вкладов
  компонентов против oracle;
- итог аудита: **наблюдаемый максимум ошибки на заранее заданной
  audit-матрице** (uTPD_observed) — НЕ «сертифицированная полная
  погрешность»: максимум на конечном наборе тестовых конфигураций
  сам по себе НЕ является доказанной глобальной верхней границей
  ошибки для всей области PR-модели; envelope действителен ТОЛЬКО
  для исследованной области T/P/составов/режимов корней (two-root,
  около слияния корней, вырожденные составы);
- для математически доказанной глобальной границы потребуются
  validated numerics, интервальные оценки или доказанный анализ
  обусловленности и погрешности; конечный набор oracle-тестов НЕ
  доказывает глобальную точность PR;
- mpmath/high-precision PR oracle — независимый числовой ОРИЕНТИР
  аудита; CoolProp — ДОПОЛНИТЕЛЬНАЯ независимая сверка там, где он
  возвращает пригодные конечные данные, но НЕ замена
  high-precision oracle;
- из uTPD_observed и коэффициента запаса уточняются
  классификационные границы (§6.6) и t_neg с явной ревизией этого
  документа; НИКАКИХ придуманных оценок погрешности.

**До завершения аудита**: uTPD НЕ имеет подтверждённой численной
границы; t_neg = −1e−10 действует как предварительный operational
margin с явной пометкой статуса в результате (§7.2,
`negativeThresholdStatus`, `uTPDStatus`). БЕЗ доступной оценки
неопределённости НЕЛЬЗЯ выдать надёжное
`no_instability_found_within_search` на основании предположения о
точности: такой исход классифицируется как `indeterminate` с явной
причиной (§6.6). Значения, знак которых нельзя надёжно
классифицировать с учётом фактической численной неопределённости,
НЕ дают права на `unstable_detected` и ведут к `indeterminate`
(§6.6). Никаких фиктивных ошибок и выдуманных гарантий точности:
точность evaluator — факт регрессий; глобальная точность PR-TPD —
предмет аудита.

### 6.6. Семантика результатов (имена согласованы с SCOPE_NOTE 4.4.4.4.1)

Единый консервативный контракт (корректирующие ревизии; первая
удалила формулировку, допускавшую `no_instability_found_within_search`
при исчерпанном бюджете без сходимости; вторая устранила дыру, в
которой надёжно отрицательное TPD МЕЖДУ t_neg и нулём не получало
ни `unstable_detected`, ни полосы неопределённости и могло
приводить к `no_instability_found_within_search`).

**Interval-based классификация знака** (§6.5): для каждой
допустимой корректно вычисленной посещённой точки с оценкой
tpdEstimate и консервативной неопределённостью uTPD интервал
[tpdEstimate − uTPD, tpdEstimate + uTPD] даёт класс точки:

- **C1 (надёжно отрицательная)**: верхняя граница интервала
  надёжно ниже нуля И ниже действующего operational margin
  (tpdEstimate + uTPD < t_neg; пока t_neg действует как
  предварительный; при отдельном отказе от margin условие —
  верхняя граница < 0);
- **C2 (отрицательная без запаса)**: t_neg <= tpdEstimate + uTPD
  < 0 — отрицательность надёжна, но запас относительно margin
  недостаточен;
- **C3 (знак неопределён)**: интервал пересекает ноль
  (tpdEstimate − uTPD <= 0 <= tpdEstimate + uTPD);
- **C4 (надёжно неотрицательная)**: нижняя граница интервала
  неотрицательна (tpdEstimate − uTPD >= 0).

Классификация любого знака требует оценки uTPD в силе: до
интеграции результатов аудита (§6.5) ни C1, ни C4 не могут быть
установлены, и verdict деградирует до `indeterminate` с явной
причиной — консервативно и без придуманных оценок.

**Verdict-правила**:

- **`unstable_detected`** — найдена ДОПУСТИМАЯ корректно
  вычисленная ПОСЕЩЁННАЯ точка (стартовая, промежуточная итерация
  любой попытки, включая fallback/Jacobian/line-search, §2.4)
  класса C1. Сходимость породившей попытки НЕ требуется.
  **ПРИОРИТЕТ**: одного класса C1 достаточно для вывода о
  неустойчивости feed-фазы в рамках выбранной PR-модели и принятых
  данных — даже при наличии других неудавшихся/несошедшихся
  попыток.
- **`no_instability_found_within_search`** — ВСЕ обязательные
  попытки достигли критериев сходимости (6.1 И 6.3); ВСЕ
  обязательные ветви рассчитаны; ВСЕ предусмотренные грани
  обследованы (faceEnumeration = 'complete' в пределах лимита
  перечисления); численных отказов нет; И для ВСЕХ посещённых
  допустимых точек установлен класс C4 (нижняя граница интервала
  неотрицательна). Требует ДОСТУПНОЙ оценки uTPD (§6.5): без
  доступной оценки неопределённости надёжное
  `no_instability_found_within_search` НЕ выдаётся на основании
  предположения о точности — исход классифицируется как
  `indeterminate` с явной причиной. Отрицательное TPD между t_neg
  и нулём (класс C2) НЕ приводит к
  `no_instability_found_within_search` НИ ПРИ КАКИХ условиях. Это
  НЕ доказательство глобальной устойчивости: формулировка
  описывает только выполненный поиск.
- **`indeterminate`** — класса C1 нет, НО: есть точка класса C2
  (недостаточный отрицательный запас) или C3 (знак неопределён);
  ИЛИ хотя бы одна обязательная попытка не сошлась
  (max_iterations), завершилась numerical_failure или была
  недопустима; ИЛИ обязательная ветвь не рассчитана; ИЛИ
  перечисление граней осталось неполным сверх лимита; ИЛИ оценка
  uTPD недоступна (аудит не завершён/не интегрирован, §6.5).
- Статус `stable` НЕ выдаётся ни при каких условиях. Математическая
  глобальная полнота конечного multi-start НЕ утверждается. Имена
  перечислены в PR_TANGENT_PLANE_DISTANCE_SCOPE_NOTE (границы
  4.4.4.4.1), где зафиксировано, что сам evaluator их не выдаёт:
  поисковые заключения — предмет 4.4.4.4.2.

### 7.3. Тест-план (обязательный минимум)

Каждый тест фиксирует И семантику, И численные значения против
НЕЗАВИСИМЫХ оракулов (прямое вычисление формулы в тесте), никогда —
против самого производственного TPD-вычислителя.

1. **Идеальный газ / KL-предел**: lnPhi = 0; g(w; z) = KL(w||z) >= 0
   с минимумом в w = z; все попытки сходятся к тривиальной точке
   (feed — неподвижная точка SS); verdict
   `no_instability_found_within_search`.
2. **Синтетический надёжно отрицательный TPD**: синтетическая
   конфигурация (НЕ из каталога, НЕ заявляемая как физическая) с
   TPD ~ −1e−3 в точке, которую посещает хотя бы одна попытка;
   verdict `unstable_detected`, bestVisitedTpd — класс C1
   (tpdEstimate + uTPD < t_neg при синтетической uTPD, заданной
   тестом). Тест
   ДОКУМЕНТИРОВАН как синтетический: механика поиска, НЕ
   экспериментальная валидация EOS.
3. **Чувствительность к начальным приближениям**: синтетический
   случай с двумя стационарными точками (разные знаки TPD):
   пароподобный и жидкоподобный старты сходятся к РАЗНЫМ точкам;
   тест фиксирует, что один старт недостаточен (без второго старта
   verdict был бы ложным), и что попытки сохраняют обе точки.
4. **Одинаковый состав на двух ветвях** (корректирующая ревизия):
   w = z на ветви feed — идентичное состояние, точный +0; ТОТ ЖЕ
   состав на альтернативной ветви (two-root конфигурация) —
   вычисленное состояние с TPD ≠ 0 в общем случае. Проверяется:
   альтернативная точка НЕ подменяется exact-zero; её TPD и
   вклады совпадают с независимым оракулом (прямой пересчёт
   формулы g); обе записи присутствуют в attempts с разными
   selectedRoot и rootLabels.
5. **Single-root и two-root**: two-root — обе ветви выполняются
   независимо (logicalLabels по одной, rootLabels различны),
   старт feed_alternative_branch присутствует; single-root — на
   каждый старт/грань РОВНО одна попытка с logicalLabels =
   ['vapor','liquid'], singlePhysicalRoot = true, предупреждение
   в notes; счётчики attemptCount/prEvaluations НЕ задвоены
   (бюджет одного исполнения, а не двух).
6. **Перестановка компонентов**: перестановка входных массивов не
   меняет verdict, bestVisitedTpd и tpd побитово (канонический
   порядок итерации).
7. **Нулевые доли и границы носителя**: z_i = 0 запрещает w_i > 0
   (`support_violation`, пробная попытка не создаётся); минимум на
   грани 2-компонентной смеси обнаруживается граничным поиском;
   faceEnumeration корректен.
8. **Отслеживание лучшей посещённой точки** (корректирующая
   ревизия): траектория, где минимум TPD достигается в
   промежуточной итерации (не в финальной): bestVisitedPoint.tpd
   <= finalStationaryPoint.tpd; состав, ветвь, номер итерации и
   вклады bestVisitedPoint сохранены; глобальный bestVisitedTpd =
   min по всем попыткам (не только сошедшим).
9. **Отрицательная точка в незавершённой попытке + приоритет**:
   (a) попытка упирается в max_iterations ПОСЛЕ посещения надёжно
   отрицательной точки → verdict `unstable_detected` (найденное
   значение НЕ потеряно), даже если другие попытки тоже неудачны;
   (b) все обязательные попытки сошлись, отрицательных нет →
   `no_instability_found_within_search`; (c) хотя бы одна
   обязательная попытка не сошлась, надёжно отрицательных нет →
   `indeterminate`.
10. **Пограничные значения (interval-based классификация)**: точка
   класса C1 (tpdEstimate + uTPD < t_neg) → `unstable_detected`;
   точка класса C2 — надёжно отрицательная между t_neg и нулём
   (например, TPD = −5e−11 при uTPD много меньше 1e−11) →
   `indeterminate` (недостаточный отрицательный запас) и НИКОГДА
   `no_instability_found_within_search`; точка класса C3 — интервал,
   пересекающий ноль → `indeterminate` (§6.5/§6.6).
11. **Неконечные значения**: NaN/Infinity lnPhi в PR-пересчёте →
   `numerical_failure` попытки; NaN не попадает в
   tpd/bestVisitedTpd/searchVerdict.
12. **Повторяемость**: два вызова с одним входом — побитово равные
   результаты (все поля, включая counts).
13. **Бюджет и дедупликация**: counts.faceCount/attemptCount/
   prEvaluations корректны; prEvaluations <= maxPrEvaluations;
   дедупликация стартов (|S| = 1 → один старт на грань; совпадение
   uniform/pair при |S| = 2 не удваивает бюджет).
14. **Масштаб Wilson Y** (вторая ревизия): для
   wilson_vapor_like/wilson_liquid_like начальное состояние
   итераций — ln Y^(0) = ln z ± ln K с СОХРАНЁННЫМ абсолютным
   масштабом (ΣY^(0) ≠ 1 в общем случае); в PR и evaluator входит
   ТОЛЬКО нормированный w^(0) = Y^(0)/ΣY^(0) (§2.3).
15. **Запрещённая нормализация (негативный контроль)**: нормализация
   Wilson Y с последующим использованием Y = w как начального
   состояния даёт ДРУГОЕ начальное состояние (ΣY^(0) = 1) и НЕ
   допускается: тест проверяет, что итерации стартуют с
   сохранённого ln Y^(0) (первая SS-итерация и трекинг ΣY
   согласованы с исходным масштабом z·K / z/K, а не с w) (§2.3).
16. **Механика g***: на стационарной точке ln Y + lnPhi(w) − h = 0,
   вся скобка g* равна −1, g* = 1 − ΣY = 1 − exp(−g_sp) — против
   независимого оракула в тесте (§1.3).
17. **Классификация C2**: TPD = −5e−11 при неопределённости,
   существенно меньшей 1e−11, НЕ даёт
   `no_instability_found_within_search` (см. п. 10).
18. **Классификация C3**: интервал TPD посещённой точки пересекает
   ноль → `indeterminate`.
19. **Классификация C4 + сходимость**: все интервалы посещённых TPD
   неотрицательны, все обязательные попытки сошлись, uTPD доступна
   → `no_instability_found_within_search`; при недоступной uTPD тот
   же исход → `indeterminate` с явной причиной (§6.5/§6.6).
20. **Переход fallback** (вторая ревизия): попытка исчерпывает
   N_SS_max без сходимости → переключение на fallback в резерве
   N_fallback_max; N_total_max и maxPrEvaluations НЕ превышены;
   счётчики проверяются точно, включая отказные PR-вызовы (§2.5,
   §4.4, §6.2).
21. **Точки fallback/Jacobian/line-search**: надёжно отрицательная
   точка, вычисленная в line-search, численном якобиане или в
   неудавшемся fallback, сохранена как bestVisitedPoint своей
   попытки и участвует в глобальном bestVisitedTpd и вердикте (§2.4,
   §2.5).
22. **Root-метаданные точки** (вторая ревизия): single-root попытка
   — каждая visited point хранит фактический selectedRoot (Z) и
   rootLabels = ['vapor', 'liquid']; искусственная одиночная
   логическая метка НЕ назначается (§7.2).
23. **Повторяемость и точные счётчики PR**: два вызова с одним
   входом — побитово равные результаты, включая prEvaluations
   (успешные + отказные) и все счётчики бюджета (§4.4, §7.2).

Дополнительно: отсутствие поля `stable` (фиксация множества
verdict-имён); нарушение суммы состава старта → `invalid_start`;
бюджет: фактическое число PR-пересчётов <= лимита.
