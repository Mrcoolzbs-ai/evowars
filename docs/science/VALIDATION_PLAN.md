## Уровень 1 — математические инварианты (частично реализовано, расширить)

- Единицы: константы и конвертации (есть: units.test.ts).
- Масса/элементы/заряд: элементный баланс реакций (есть); распространить на
  решатели равновесия/кинетики (§5.2 CHEMISTRY): суммы до 1e-12 относительных.
- Неотрицательность концентраций: инвариант решателей (новое, 4.5).
- Устойчивость методов: энергия leapfrog (4.6), монотонность профилей
  гидростатики (4.8), сходимость равновесного решателя (4.4).
- Формат: инвариантные тесты НЕ зависят от каталогов данных (только формулы).
- Ядро (4.1.1): аудиты сохранения вещества/элементов/заряда/энергии
  возвращают СТАТУС (balanced | imbalanced | approximate |
  not_verifiable); balanced:true допускается только при полном
  'balanced' — неизвестный запас энергии (storedJ = null), исключённый
  вид или несмешиваемые основания делают аудит непроверяемым, а не
  успешным (регрессионные тесты coreFluxLedger).
- Массово-молярные преобразования: convert в/из кг ДО умножения/деления
  на молярную массу; переполнение → ошибка 'overflow', а не ±Infinity
  (регрессия coreReservoir: 1000 г / 0.018 кг/моль = 55.5556 моль).
- Ядро (4.1.1.2), полнота балансов и защита данных:
  (а) тройное различие «инвентарь не задан» ≠ «инвентарь пуст» ≠
  «запас вида = 0»: только неизвестное состояние делает аудит
  непроверяемым; известные пустота/ноль проходят честную проверку;
  явный materialApplicability 'not_applicable' — законное исключение
  (резервуар без материи по природе), отсутствие поля — нет;
  (б) auditReservoirFluxes проверяет объединение резервуаров «до» ∪
  «после» ∪ затронутых потоками: обязательный инвариант «нет
  применённого потока → Δ = 0» для известного инвентаря; изменение
  без записи потока — расхождение с reservoirId;
  (в) в ограниченной временной области исключённые untimed-записи не
  позволяют объявить balanced (untimed ≠ out-of-range — разные
  диагностики; includeUntimed — на ответственность вызывающего);
  (г) exclusions обязательных вкладов делают итог not_verifiable,
  а не balanced;
  (д) Storage: повреждённый корневой JSON → отказ записи
  (storage_unreadable) с сохранением исходных данных
  (регрессионные тесты coreFluxLedger, corePersistence,
  coreWorldState, coreReservoir).

## Уровень 3 — эталонные планетарные сценарии

Правило: упрощённая модель НЕ обязана воспроизводить объект полностью; для
каждой величины заранее фиксируется допуск и значение «что делаем, если не
совпало» (диагностика, а не подгонка).

Дополнительные правила ревизии 4.0.1:

- **g_n ≠ локальное g**: 9.80665 м/с² — ТОЧНОЕ стандартное ускорение по
  определению (не наблюдаемая величина и не значение, установленное
  IAU 2015); локальная гравитация поверхности Земли — отдельная величина
  (~9.78–9.83 м/с², зависит от широты и фигуры). Тесты не приписывают
  стандартное ускорение планете и не смешивают эти величины.
- **Предел Роша**: расчёт только по плотностной форме с плотностями ОБОИХ
  тел; тест чувствительности: изменение ρ_s меняет d_R как ρ_s^(−1/3)
  (уменьшение плотности спутника расширяет предел) при неизменном ρ_p.
- **Интеграторы**: шаг задаётся ОТНОСИТЕЛЬНО периода (например, dt = P/N);
  обязательна проверка сходимости при уменьшении шага (N → 2N → 4N с
  ожидаемым порядком убывания ошибки); локальная ошибка шага и
  накопленная глобальная ошибка — РАЗДЕЛЬНЫЕ метрики, обе с допусками.
- **Равновесные константы**: стандартное состояние фиксируется в тесте;
  сравнение ведётся по log10(K) с допуском в dex; K без указанного
  стандартного состояния не сравнивается.
- **Производительность**: любые цели времени задаются ТОЛЬКО с указанием
  оборудования, среды (браузер/Node) и состава задачи (размер сети, число
  шагов); без этого — не критерий.
- **Климат (RCM)**: калибровка НЕ допускается исключительно под одну
  эталонную температуру (288 K): после подгонки обязательна независимая
  проверка остальных параметров (профиль T(z), потоки на границах,
  парниковый разрыв Венеры, Титан); иначе фиксируется «калибровка по
  одной точке» как ненаучная.

## Уровень 4 — регрессионные сценарии

- **Golden worlds**: фиксированный набор seed → `generateWorld` → хэш
  сериализованного состояния. Хэш меняется ТОЛЬКО при смене engine/data
  версии; иначе — регрессия. Обновление хэшей — осознанный коммит.
- **Сохранение законов при расширении**: после каждого этапа прогон
  полного набора предыдущих уровней (CI уже делает это; формализовать
  обязательность).
- **Кросс-подсистемная согласованность**: инвентарь химии == столб
  атмосферы == фазовый скрининг (одна температура-политика после 4.2);
  тесты на запрет двойных источников истины (например, запрет легаси-ветки
  характеристик после 4.1 — проблема 2.6).

## Уровень 5 — чувствительность и неопределённость

- Одномерные развёртки: T_eq(A) для A ∈ [0.1, 0.7] (ожидаемая монотонность
  и диапазон), P_sat(T) в диапазоне Antoine ± экстраполяционная пометка.
- Монте-Карло по неопределённостям входов (диапазоны PhysValue.range):
  распределение выходов; для линейных цепочек — аналитическая проверка
  квадратичным суммированием.
- Формат: каждый отчёт теста указывает, какие входы варьировались и
  какие допуски нарушены; тест провален, если результат нефизичен
  (отрицательные количества, S_i NaN и т.п.), а не «слишком широкий».
